## 摘要

**写作要点**（成文 300～500 字）：
- 一句话问题定义：基层民警在"无高级设备、无精确坐标"条件下，需要快速掌握指定基站的真实覆盖范围，而现有手段存在专业门槛高、设备依赖强、情报滞后等短板。
- 一句话方法概述：基于普通 Android 手机免 root 采集蜂窝测量报告（1Hz 定时打点），对上级提供的四类基站参数格式（ECI / NCI / LAC+CI / 经纬度+半径）做目标基站匹配，多警力协同绕行采集后，以 RSRP 阈值等值线 + 凸包 + 缓冲带 + IDW 插值重建可行动的覆盖边界，并给出低/中/高三档置信度。
- 一句话结果表述：完成系统设计与三场景（城市/郊区/室内）试验验证，各项指标以目标值口径给出，实测值【待试验后填写】。
- 关键词建议（4～6 个）：基站覆盖；位置打点；RSRP；覆盖边界重建；协同采集；公安移动应用。

## 1 研究背景与问题定义

### 1.1 研究背景

#### 1.1.1 基层公安移动通信保障的现实需求
- 要点：涉稳事件处置、走失人员查找、案件现场勘验等场景中，民警常需要回答"某个手机号当前最可能驻留在哪个基站、该基站信号覆盖到哪里"这类问题；基站覆盖范围是缩小搜寻圈、布控卡口选点的关键情报。
- 要点：基层单位普遍缺乏专业网优设备（扫频仪、路测终端）与专职网优人员，覆盖情报主要依赖协调运营商，时效难以保证。

#### 1.1.2 基站覆盖情报获取的空白
- 要点：运营商网络侧数据（OMC 话统、MR 测量报告）不对外开放且粒度滞后；公众类信号地图 App 面向消费场景，数据合规性与使用边界不适配执法需求。
- 要点：由此形成"基层一线知道要什么、却拿不到现成数据"的覆盖情报空白。

#### 1.1.3 普通终端测量能力的成熟
- 要点：Android 公开 API（TelephonyManager）已能提供本机服务小区与邻区测量量，使"用警用装备化的普通手机自己做路测"成为可能，这是本作品的技术可行性基础。

### 1.2 问题定义

#### 1.2.1 条件约束
- 明确两类约束：**无高级设备**（只有普通 Android 手机与既有警力）；**无精确坐标**（上级提供的基站参数可能是 ECI / NCI / LAC+CI，甚至只有大致经纬度+半径）。

#### 1.2.2 核心科学问题
- 问题表述：在稀疏、非均匀、有噪声的地面移动采样条件下，如何重建目标基站的可行动覆盖边界，并量化结果可信程度。
- 拆解为三个子问题：(1) 免 root 条件下如何稳定获得可用测量量；(2) 稀疏样本如何支撑边界重建（插值与等值线提取）；(3) 采样不充分时如何诚实表达不确定性（置信度分档）。

### 1.3 研究目标与范围声明

#### 1.3.1 研究目标
- 目标 1：实现四类基站参数输入格式的统一解析与目标小区匹配；
- 目标 2：实现 1Hz 定时位置打点与蜂窝测量联合采集，免 root、最小权限；
- 目标 3：实现覆盖边界重建算法链（等值线/凸包/缓冲带/IDW）与三档置信度输出；
- 目标 4：实现多人协同采集与 CSV/GeoJSON/KML 成果导出；
- 目标 5：完成三场景试验验证并形成可复用的采集规程。

#### 1.3.2 明确不做（范围边界声明）
- 逐条声明：不做测速、不做网络 KPI 统计、不做自动呼叫测试计划、不做信令事件解码、不做锁网锁频。此节是合规审查与答辩的关键防线，必须显性成文。

## 2 相关工作与现有工具局限

### 2.1 网络侧与运营商侧手段

#### 2.1.1 专业网优工具与路测设备
- 要点：扫频仪、专业路测软件可给出高精度覆盖图，但设备昂贵、操作专业、不宜普及到基层所队。

#### 2.1.2 协调运营商取数
- 要点：时效受流程制约，且通常只能给出规划数据或话统口径的覆盖估计，与"当前实测"存在偏差。

### 2.2 公众类众包信号地图应用
- 要点：数据来源于消费者众包，覆盖估计面向用户体验优化；数据更新、区域完整性、用途合规性均无法满足执法场景要求；本作品不使用、不依赖其任何数据或资源。

### 2.3 终端侧无线测量能力

#### 2.3.1 Android Telephony 测量接口
- 要点：`getAllCellInfo` 与 `registerTelephonyCallback`（`onCellInfoChanged` 系列）可获取服务小区/邻区的 LAC/TAC、CI、PCI、EARFCN、RSRP/RSRQ 等量；不同制式（GSM/WCDMA/LTE/NR）返回的 CellInfo 子类不同，需统一归一化。

#### 2.3.2 免 root 约束下的能力边界
- 要点：免 root 无法读取基带日志、无法锁频锁网；本作品明确将自身能力边界定义在"公开 API + 最小权限"，并说明该边界与执法需求（覆盖范围实测）恰好匹配。

### 2.4 覆盖重建相关算法基础
- 要点：空间插值（IDW、克里金）与等值线提取（Marching Squares）是地理信息领域成熟方法；凸包计算（Andrew 单调链）是计算几何经典算法。本工作在于四者面向"稀疏车载/徒步采样 + 执法可用性"的工程化组合，而非提出新算法。

- 用对比表收束本章，导出本作品定位：**面向基层、零专用设备、当场实测、成果可导出、合规可控**。

## 3 系统设计

### 3.1 总体架构

#### 3.1.1 设计原则
- 原则 1：终端能力最大化、后端依赖最小化（断网亦可单机作业）；
- 原则 2：数据本地优先，上云需民警主动操作；
- 原则 3：全部代码自研，不引入逆向资源；
- 原则 4：输出"可行动"成果（边界、置信度、可直接导入的格式），而非原始数据堆砌。

#### 3.1.2 分层架构
- 端侧 App 层：参数输入、采集打点、本地存储、可视化、导出、AI 助手；
- 协同服务层：Ktor + WebSocket，负责任务分区下发与全员数据汇聚；
- 基础设施层：阿里云 ECS + docker-compose 部署。
- 说明：后端仅服务协同场景，单机全流程可独立完成，此设计直接回应"无高级设备"约束。

### 3.2 数据流设计

#### 3.2.1 单机数据流
- 输入基站参数 → 定时打点（1Hz：GPS 位置 + CellInfo 测量联合帧）→ JSONL 追加落盘 → 现场过滤（onTarget 判定）→ 覆盖分析 → 边界渲染/导出。

#### 3.2.2 协同数据流
- 队长创建任务、划定分区 → 队员领分区采集 → WebSocket 汇聚位置/轨迹/样本/照片 → 队长端实时总览 → 统一分析出图。

### 3.3 功能模块设计

#### 3.3.1 基站参数输入模块
- 要点：四格式统一建模——ECI（LTE，eNB ID+Cell ID）、NCI（NR，gNB ID+Cell ID）、LAC+CI（2G/3G）、经纬度+半径（仅有粗略位置时划定初始搜索圈）；解析器输出统一的"目标小区标识集"，供打点匹配模块比对 servingCi 等字段。
- 要点：格式自动识别与人工复核并行，避免现场误配。

#### 3.3.2 采集与打点模块
- 要点：1Hz 定时打点，每帧联合记录位置（lat/lon/accuracy/provider）与蜂窝测量（RAT/MCC/MNC/LAC+TAC/CI/PCI/EARFCN/RSRP/RSRQ/SINR/RSSI/邻区数与邻区 CI 列表/WiFi 计数）；onTarget、targetSeen、targetRsrp 三个字段标记本帧是否命中目标小区。
- 要点：打点不依赖网络连通，全部可离线。

#### 3.3.3 覆盖分析模块
- 要点：样本按 RSRP 阈值过滤 → 栅格化（IDW 插值）→ 等值线提取（Marching Squares）→ 外包络（凸包）→ 安全外扩（缓冲带）→ 置信度评估；各算法可单独开关，输出叠加展示。

#### 3.3.4 多人协同模块
- 要点：角色分队长/队员；任务分区（多边形）在队长端划定；队员端上报位置、轨迹、样本、现场照片；断线重连与补传机制（设计要点，机制细节【待填：实现章节确认】）。

#### 3.3.5 导出模块
- 要点：CSV（22 列原始帧）、GeoJSON（边界/轨迹，便于 GIS 平台导入）、KML（便于警用地图/谷歌地球类工具查看）；导出文件命名含任务号与时间戳。

#### 3.3.6 AI 助手模块
- 要点：接入 DeepSeek；三类功能——拍照场景分析（现场环境记录辅助）、蜂窝技术答疑、越界拒答（涉及个人隐私追踪、攻击性内容等一律拒绝）；声明 AI 输出仅供参考，不替代人工判断。

#### 3.3.7 新手向导与法律声明
- 要点：首启向导（四步走：输参数→绕圈走→看边界→导出）；首次使用强制阅读法律声明（仅限合法执法与教学用途）。

### 3.4 关键算法设计

#### 3.4.1 RSRP 阈值等值线
- 要点：以业务可用的 RSRP 阈值为基准（已定，源自 `CoverageFitter.kt`：默认 −110 dBm，6 档可配，借鉴 CellularPro 6 档评级思路；另有样本门槛——总有效样本 < 8 不拟合，GPS 精度 > 60 m 的样本剔除），"达标样本"构成的连续区域即为有效覆盖区；等值线是达标/不达标的分界。

#### 3.4.2 凸包（Andrew 单调链）
- 要点：对达标样本点集求凸包，O(n log n)；用于给出覆盖区域的外包络骨架，抗单点噪声优于直接连线。

#### 3.4.3 缓冲带（边法线平移 + 顶点圆弧采样）
- 要点：对凸包每条边沿外法线方向平移缓冲距离（单位米；已定，源自 `CoverageFitter.kt`：25 m 基础值 + 平均定位精度 × 0.5，定位越差边界越保守），顶点处以圆弧采样衔接，形成圆角外扩带；缓冲带表达的"边界±误差余量"便于实战留裕度。

#### 3.4.4 IDW 插值（p=2）
- 要点：反距离加权，权重 w=1/d²，把离散样本栅格化，为等值线提取提供规则场；讨论 p=2 的选择理由（对近距离样本敏感、计算简单、无需样本统计前提）。

#### 3.4.5 Marching Squares（16 case + 鞍点消歧）
- 要点：逐栅格单元按四角与阈值的大小关系分类为 16 种 case，抽取等值线段并连接；对 5/10 两种鞍点 case 采用单元中心均值消歧，保证拓扑一致。

#### 3.4.6 置信度模型（样本量因子 × 16 扇区方向覆盖度）
- 要点：以凸包质心为原点把方位均分 16 扇区（内点落入的扇区数/16 为方向覆盖度）；置信度得分 = (样本量因子 × 0.5 + 方向覆盖度 × 0.5) × 100，其中样本量因子 = min(1, 有效样本数 / 120)（120 样本饱和）；得分 ≥ 70 且 ≥ 12/16 扇区评为「高」，≥ 40 为「中」，否则「低」（源自 `CoverageFitter.kt` 与 README）。核心立场：采样不足时明确告知"这个边界还不算硬"，禁止过度承诺。

## 5 试验设计与数据

### 5.1 试验目的与假设
- 目的：验证采集可行性、边界重建有效性、置信度分档合理性；假设：绕圈+横穿路线可显著提升方向覆盖度。

### 5.2 试验场景设计
- 三场景：城市密集城区（多遮挡、多小区重叠）、郊区（开阔、单站主导）、室内（弱覆盖、驻留采样）；选址标准与路线设计详见《试验数据采集计划.md》，本节只写设计依据。

## 7 合规与安全设计

### 7.1 合规立场
- 要点：全部代码自研（路线 B），未对任何商业 App 逆向或复制资源；仅用于合法执法与教学；参选材料中明确声明。

### 7.2 数据安全设计
- 要点：定位与测量数据本地优先存储；上传须民警主动操作；最小权限（无 READ_PHONE_STATE）；导出文件由办案单位自行管控。

### 7.3 法律与伦理声明
- 要点：内嵌法律声明页面，首次使用强制阅读；明确禁止用于侵犯公民个人信息等违法用途。

### 7.4 应用边界与禁止行为
- 要点：重申"明确不做"清单并解释原因（越界功能会引入合规风险，与产品定位冲突）。
