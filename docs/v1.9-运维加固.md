# v1.9：运维加固（版本号 / 房间清理 / 管理鉴权）

## 一、改动
| # | 内容 | 说明 |
|---|---|---|
| 1 | 版本号 | `GET /` 的 `version` 从 `0.1.0` 改为 `1.9.0`（`SERVER_VERSION` 常量） |
| 2 | 默认 TTL 7 → **3 天** | `WEILIE_ROOM_TTL_DAYS` 未设置时按 3 天回收无活动房间 |
| 3 | **管理口令** | 新增 `WEILIE_ADMIN_TOKEN`；配置后 `GET /api/rooms` 需带 `X-Admin-Token` |
| 4 | **管理员清理接口** | `POST /api/admin/purge-rooms?days=3&emptyOnly=true`（需 `X-Admin-Token`） |

## 二、接口
```bash
# 房间清单（需管理口令；未配置 WEILIE_ADMIN_TOKEN 时保持公开）
curl -H "X-Admin-Token: <你的口令>" http://47.89.181.85:8080/api/rooms

# 清理 3 天前的空房间（emptyOnly=false 可删有数据的旧房间，慎用）
curl -X POST -H "X-Admin-Token: <你的口令>" \
  "http://47.89.181.85:8080/api/admin/purge-rooms?days=3&emptyOnly=true"
# -> {"ok":true,"removed":N,"scanned":M}
```

未配置 `WEILIE_ADMIN_TOKEN` 时：`/api/admin/purge-rooms` 返回 **503**；`/api/rooms` 保持公开（向后兼容）。

## 四、上线步骤（在已部署 v1.8 的机器上）
```bash
# 1) 备份
sudo systemctl stop weilie
sudo cp -a /opt/weilie/weilie-server-all.jar /opt/weilie/weilie-server-all.jar.bak.$(date +%Y%m%d%H%M)
sudo tar czf /opt/weilie/data-backup-$(date +%Y%m%d%H%M).tgz -C /opt/weilie data

# 2) 替换 jar
sudo cp weilie-server-all.jar /opt/weilie/weilie-server-all.jar
sudo chmod 644 /opt/weilie/weilie-server-all.jar

# 3) 更新 systemd（加 TTL 与 ADMIN_TOKEN；TOKEN 换随机串）
sudo vi /etc/systemd/system/weilie.service
#   Environment=WEILIE_ROOM_TTL_DAYS=3
#   Environment=WEILIE_ADMIN_TOKEN=<32 位随机串>
sudo systemctl daemon-reload && sudo systemctl start weilie

# 4) 验证
curl -s http://47.89.181.85:8080/ | grep 1.9.0
curl -s -H "X-Admin-Token: <口令>" http://47.89.181.85:8080/api/rooms | head -c 200
```

## 五、风险
- **TTL 改成 3 天**：3 天无活动的房间会被自动回收，包括有任务区的房间；如需保留请调大 `WEILIE_ROOM_TTL_DAYS`；
- **管理口令丢失**：只能停服改 systemd 环境变量再启动，不影响客户端；
- 清理不可恢复；建议先 `GET /api/rooms` 确认再 purge（可先 `emptyOnly=true`）。
