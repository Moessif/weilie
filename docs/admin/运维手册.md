# 围猎管理平台 · 运维手册

适用版本：服务端 **v1.12.0**（管理站 M1+M2），部署在阿里云 ECS `47.89.181.85:8080`。

## 一、访问与账号

| 项 | 值 |
| --- | --- |
| 管理站地址 | `http://47.89.181.85:8080/admin/` |
| 超管账号 | `admin` |
| 超管密码 | 本地 `tools/superadmin-password.txt`（18 位，已轮换；服务器上以 systemd 环境变量 `WEILIE_SUPERADMIN_PASSWORD` 为准） |
| 手机端接口 | `/api/client/activate`、`/login`、`/me`、`/change-password` |
| 机器接口令牌 | `WEILIE_ADMIN_TOKEN`（`/api/rooms`、`/api/admin/purge-rooms` 需带 `X-Admin-Token`），同样在 unit 环境变量里 |

登录流程：浏览器打开管理站 → 用户名/密码 → 首次登录强制改密 → 进入仪表盘。会话 8 小时滑动过期、30 分钟空闲过期；连续 5 次密码错误锁 15 分钟。

## 二、日常操作

### 1. 开通一个组织

1. 侧栏「组织管理」→「新建组织」：填组织名、编码（如 `CUPL01`）、联系人/电话、配额（用户数/房间数/存储）。
2. 勾选「同时创建组织管理员」→ 填管理员用户名 → 提交后**一次性弹出初始密码**（只显示一次，请立即转交）。
3. 组织管理员登录后即可在本组织范围内建用户、发激活码。

> 组织也可通过公开接口 `POST /api/admin/organizations/apply` 自助提交申请，超管在「组织管理 → 申请审核」通过或驳回。

### 2. 建用户并发放激活码

1. 「用户与账号」→「新建用户」（或「批量导入」粘贴 CSV：`username,displayName,phone`）。
2. 行操作「发激活码」→ 生成 8 位一次性码（7 天有效，同一用户同用途旧码自动作废）。
3. 线下/微信把码发给民警：手机端「激活」→ 输入码 → 设置密码（≥8 位）→ 绑定当前设备。
4. 换机：管理站「解绑设备」后可重新激活；忘记密码：管理站「重置密码」并重新发码。

### 3. 房间与任务

「房间与任务」页面：

- 顶部 tab 按状态筛选：在线（有成员且 30 分钟活跃）/ 闲置（3 天内活跃）/ 已关闭。
- 搜索框支持房间号、房间名、邀请码。
- 行操作：
  - **详情**：成员在线状态与位置、任务区（圆形/多边形）、标点、最近 200 个采样点（Canvas 散点图）。
  - **导出**：CSV / GeoJSON / KML（与客户端导出同格式，服务端生成）。
  - **关闭**：立即从内存移除并删除落盘采样（不可恢复，操作留审计）。
- 右上「清理空房」：按天数（默认取当前 TTL）+「只清空房」清理，返回删除数量。

### 4. 取证照片

- 卡片网格显示缩略图（`data/photos/<code>.jpg`）；未上传原图的记录显示占位，但登记与验真信息仍可查。
- 点击卡片打开大图 + 拍摄时间/坐标/设备/SHA-256/备注，可跳 `/v/<code>` 网页验真页。
- 支持按「普通/可疑」、关键词（验证码/哈希前缀/设备/备注）、「只看已上传原图」筛选。

### 5. 审计日志

- 记录所有管理端与手机端关键操作：登录、改密、组织/用户增减、发码/作废、重置密码、解绑设备、房间关闭/清理、设置修改。
- 等级由动作推导：成功（登录/创建/激活）、警告（删除/驳回/作废/重置）、危险（失败/错误）、一般。
- 支持等级/动作/组织/关键词筛选、15 秒自动刷新、导出 CSV（UTF-8 BOM，Excel 可直接打开）。

### 6. 系统监控与设置

- **系统监控**：版本、运行时长、JVM/CPU/线程/堆、房间与在线规模、WS 连接与消息数、采样/照片/限流/错误/导出计数、数据目录与磁盘剩余。
- **系统设置**：
  - 房间 TTL（1~30 天，保存即写 `settings` 表，后台每 10 分钟一轮清理按新值执行）。
  - `WEILIE_REQUIRE_TOKEN` 为环境变量，页面只读显示；如需强制入房令牌，改 unit 后重启。
  - 修改密码。

## 三、发布新版本

```powershell
# 1) 本地构建（工程自带 wrapper 在离线环境会超时，用本机 gradle 8.9 + JDK 17）
$env:JAVA_HOME='C:\AndroidDev\jdk-17.0.2'
cd weilie-platform\server
C:\AndroidDev\gradle-8.9\bin\gradle.bat test fatJar --console=plain

# 2) 前端产物打进 jar 资源
cd ..\web; pnpm run build
Remove-Item ..\server\src\main\resources\admin -Recurse -Force
Copy-Item dist ..\server\src\main\resources\admin -Recurse
cd ..\server; C:\AndroidDev\gradle-8.9\bin\gradle.bat test fatJar --console=plain

# 3) 上传并部署（脚本会校验 sha256、备份 jar 与 data、安装、重启、验活）
$sha=(Get-FileHash build\libs\weilie-server-all.jar -Algorithm SHA256).Hash.ToLower()
workbench upload build\libs\weilie-server-all.jar /tmp/weilie-platform-new.jar -i i-0xieiymktekjfhe5b80q -r us-east-1 -f
workbench upload ..\tools\deploy-admin-m1.sh /tmp/deploy-admin.sh -i i-0xieiymktekjfhe5b80q -r us-east-1 -f
workbench exec --command "chmod +x /tmp/deploy-admin.sh && bash /tmp/deploy-admin.sh $sha" -i i-0xieiymktekjfhe5b80q -r us-east-1
```

> 部署脚本只有在首次部署（unit 里还没有 `WEILIE_SUPERADMIN_*`）时才需要 `/tmp/weilie-admin.env`；日常升级可跳过该步（脚本会因缺文件报错，但 jar 已安装，随后手动 `systemctl restart weilie` 即可）。

验证清单：`systemctl is-active weilie` → active；`/api/health` → `{"ok":true}`；`/` → `version 1.12.0`；`/admin/` → 200；登录管理站 → 仪表盘有数字；任取一房间打开详情。

## 四、备份与恢复

数据都在 `/opt/weilie/data`：

| 文件/目录 | 内容 |
| --- | --- |
| `data/admin.db`（+ `-wal`/`-shm`） | 组织、用户、激活码、会话、设置、指标快照、审计 |
| `data/photo-registry.jsonl` | 照片登记与签名（追加写） |
| `data/photos/` | 照片原图 |
| `data/snapshot.json` | 房间快照（邀请码/任务区/标点） |
| `data/rooms/<roomId>/samples.jsonl` | 房间采样落盘 |
| `data/hmac.secret`、`data/cells/opencellid.key` | 验真密钥、基站库 Key（**不要外传**） |

- 每次部署脚本自动备份：`/opt/weilie/weilie-server-all.jar.bak.<时间戳>` 与 `/opt/weilie/data-backup-<时间戳>.tgz`。
- 手工备份：`tar czf /opt/weilie/data-backup-$(date +%Y%m%d).tgz -C /opt/weilie data`；SQLite 建议先 `sqlite3 data/admin.db ".backup '/tmp/admin.db'"` 再打包。
- 恢复：停服务 → `tar xzf data-backup-*.tgz -C /opt/weilie` → `install -m 644 weilie-server-all.jar.bak.* /opt/weilie/weilie-server-all.jar` → 启动。

## 五、安全策略（已实现）

- 口令：PBKDF2-HMAC-SHA256，210000 次迭代，16 字节随机盐；不可逆存储。新建/重置账号首次登录强制改密（除 `/auth/me`、`/auth/logout`、`/auth/change-password` 外一律 403 `MUST_CHANGE_PASSWORD`）。
- 管理站会话：HttpOnly + SameSite=Lax Cookie + CSRF 常量时间校验（写操作缺 `X-CSRF-Token` 返回 403）；空闲 30 分钟、绝对 12 小时过期；改密后吊销该用户全部会话。
- 角色门：只有 `SUPER_ADMIN`/`ORG_ADMIN`/`AUDITOR` 能登录管理站；组织管理员不能提权、不能操作超管或跨组织账号。
- 登录限流：账号+IP 5 次/5 分钟，IP 维度 30 次/5 分钟兜底（第 6 次返回 429 `TOO_MANY_ATTEMPTS`）。
- 代理头：默认**不信任** `X-Forwarded-For`（限流与审计都用 socket 地址）；放在反代后面时设置 `WEILIE_TRUST_PROXY=1`。
- 房间：邀请码 8 位字母数字（SecureRandom），旧 6 位码仍兼容；入房支持 `&code=`；服务端只认自己记录的队长，客户端自报角色无效；WS 单帧 1MB、标点 2000、任务区 200 上限。
- 取证：照片上传需与登记 SHA-256 一致且为 JPEG/PNG，否则 404/409/400，原件不可被覆盖。
- 运维面：安全响应头 + `/admin` CSP、请求体 12MB 上限、`/metrics` 与 `/api/rooms` 需 `X-Admin-Token`、`/ops/status` 仅超管、`/admin/*` 路径归一化。
- 导出：CSV 中和公式注入，KML 正确 XML 转义。
- 相关环境变量：`WEILIE_COOKIE_SECURE=1`（反代下强制 Secure Cookie）、`WEILIE_TRUST_PROXY=1`（信任反代头）、`WEILIE_REQUIRE_JOIN_CODE=1`（App 升级后强制入房携带邀请码）、`WEILIE_ADMIN_TOKEN`（`/metrics`、`/api/rooms` 管理令牌）。
- 软删除：组织/用户删除置 `deleted_at`，审计与历史数据保留。
- 审计：`admin_audit` 保留 180 天（可另行归档导出）；未带邀请码入房会记录 `join_unverified`。
- 待加强：当前管理站走 HTTP，**公网暴露请尽快加 HTTPS/WSS（Caddy 反代）**，或改为 SSH/`workbench` 端口转发只在内网访问。
- 完整审计结论见 `docs/安全审计报告-2026-11-17.md`（41 项发现 / 已修 31 项 / 未修项与方案）。

## 六、常见故障

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `/admin` 显示「管理站前端尚未构建」 | jar 里没有 `admin/` 资源 | 重新构建前端并复制到 `server/src/main/resources/admin` 后重打包 |
| 登录 403 `CSRF_MISSING` | 写操作没带 CSRF | 刷新页面重新取 `/auth/me` 的 csrfToken |
| 登录 429 | 触发登录限流 | 等 5 分钟，或超管在数据库把 `fail_count/locked_until` 清零 |
| 仪表盘图表停在旧值 | 指标快照每 60s 一条 | 等 1~2 分钟刷新 |
| 房间详情采样为空 | 该房间没人采集或已清理 | 正常；可看客户端是否上报 |
| 照片「未上传原图」 | 客户端拍照后上传失败 | 属正常降级：登记与验真仍在，原图需重新上传 |
| 服务起不来 | 端口占用/SQLite 损坏 | `journalctl -u weilie -n 100`；SQLite 可用 `.recover` 修复或从备份恢复 |
