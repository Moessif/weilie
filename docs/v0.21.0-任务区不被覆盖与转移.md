# v0.21.0：任务区不被覆盖 + 转移确认 + 角色互换可操作

## 一、问题与修复
| # | 问题 | 根因 | 修复 |
|---|---|---|---|
| 1 | 队长给同一队员多次划任务，旧任务消失 | 客户端 4 处划区都把 `replace=true` 写死，服务端会软删除全部旧任务区 | 默认改为 `replace=false`（追加）；新增队长操作「清空全部任务区（重新划分）」显式清空 |
| 2 | 任务区无法转给别人 | 协议没有转移消息，`assignees` 下发后不可改 | 新增 v1.10 协议：`zoneTransferRequest/Accept/Decline` + `Zone.pendingTransferTo` |
| 3 | 队长降为队员后不能处理自己的任务 | 只有删除入口，且转移权限未定义 | 转移发起权限 = 任务归属人 **或** 现任队长；降级后仍可转移/删除自己的任务 |

## 二、协议 v1.10
```json
{"type":"zoneTransferRequest","id":"z-abc","by":"u1","to":"u2","ts":...}
{"type":"zoneTransferAccept","id":"z-abc","by":"u2","ts":...}
{"type":"zoneTransferDecline","id":"z-abc","by":"u2","ts":...}
{"type":"zoneClear","by":"u1","ts":...}
```
`Zone` 新增 `pendingTransferTo`（待确认目标，空表示无）。

服务端规则：
- 发起：`by` 必须等于发送者；发送者须是任务归属人或现任队长；目标须为队员（非观战、非自己）；同一区仅一个待确认；
- 接受：仅 `pendingTransferTo` 本人；`assignees=[to]`，清 pending；
- 拒绝：清 pending 并通知发起人；
- 目标离线：自动清 pending；
- 清空：仅队长，全部任务区软删除（审计保留）。

## 三、客户端
- 任务列表每项新增「转移」；待确认显示「待确认」；
- 选人弹窗（排除观战与自己）→ 发送请求；

- 队长任务面板新增「清空全部任务区（重新划分）」。

## 五、风险
- 行为变化：划区从「覆盖」改为「追加」，重划需显式清空；
- 协议升级：旧服务端会忽略转移消息（按钮无反应）；需先部署服务端 v1.10 再发客户端；
- 转移会**替换** assignees 为单人；多人任务需先拆分为单任务；
- 目标离线时待确认自动取消，需重新发起。
