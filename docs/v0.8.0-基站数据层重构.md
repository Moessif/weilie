# v0.8.0 基站数据获取层重构（Beta.md 四个 P0 + 两个新特性）

真机：REDMI K80 Pro（Android 17 / SDK 37），双卡 —— SIM1 中国移动 **5G SA**，SIM2 中国联通 LTE。

## 一、问题与根因

| 现象（用户/Beta.md） | 根因 | 处理 |
| --- | --- | --- |
| 输入 `1380103-1` 或 `5652901889` 目标一直「未命中」、轨迹全是空心点 | 不是编号解析问题（`1380103<<12+1 = 5652901889` 早已归一化正确）；是**服务小区取错了**：`allCellInfo` 未按卡过滤，注册小区里联通 LTE 覆盖了移动 NR | 按数据卡取小区；再按「小区广播 PLMN → 运营商」剔除别家小区（HyperOS 的 `createForSubscriptionId(subId).allCellInfo` 实测也会混入另一张卡的小区） |
| 上下两处信号评级不一致（数据栏「中等」、SIM 行「良好」） | 数据栏读的是被覆盖的 LTE RSRP(-103)，SIM 行读的是 NR SS-RSRP(-79) | SA 时服务小区=NR，`signal`/`nrSignal` 同源；NSA 时 `signal` 是 LTE 锚点、`nrSignal` 是 NR 辅载波，`targetRsrp` 按命中对象取值 |
| 移动卡是 NR_SA，却渲染「锚点 LTE」 | 只要 `dataNetworkType` 是 NR 或扫到 NR 就当 NSA | 新增 `NetMode` 状态机（`NetJudge.classify`）：NR+LTE 双注册=NSA；仅 NR 注册=SA（UI 绝不出现锚点行）；仅 LTE 注册且扫到 NR/数据网为 NR=NSA |
| `附近还有 0 个基站` 冷冰冰 | 5G SA 下多数 ROM 不返回邻区 | 新增 `neighborNote`：SA 显示「5G SA 模式下多数机型不提供邻区（系统限制）」，其他 ROM 显示「当前系统/芯片限制，未返回邻区（不影响主区命中判定）」 |
| 邻区/服务小区跨卡混排 | 只按 subId 取小区还不够（见上） | `plmnOfCell` + `NetJudge.carrierKey/operatorKey/belongsTo`：移动卡保留 460-00/02/04/07/08，联通卡保留 460-01/06/09；认不出的 PLMN（漫游、MVNO）一律保留 |

## 二、新特性

1. **未命中轨迹连线变灰**：轨迹按采样点分类分段着色 —— 主区/邻区命中段蓝色（`0xE638BDF8`），脱离目标段灰色（`0xCC94A3B8`）。百度地图与 Canvas 兜底两套实现都改了。
2. **打点间隔可手动输入**：设置 →「采集与安检」→「打点间隔」，可输入 **0.2 ~ 600 秒**（默认 1 秒）；写入 prefs 并立即作用于当前采集控制器（`SamplingController.sampleIntervalMs` 范围同步放宽到 200ms~600s）。工具箱仍保留 1s/2s/5s 快捷 chip。

## 三、代码改动

- `core/telephony/AndroidCellReader.kt`（重写 `consume` 与 `readSubCells`）
  - 新增 `NetMode`（已抽到 `NetJudge.kt`）、`nrServing`、`nrSignal`、`anchorLte`、`dataSubId`、`neighborNote`
  - 新增 `SubCells`（subId / 卡槽 / 运营商 / PLMN / 小区列表 / 是否数据卡）+ 1 秒缓存
  - 新增 `readDataRat(subId)`：先按卡取 `dataNetworkType`，再回落全局
  - Debug 版每秒打印 `CellReader: sub=… slot=… 运营商 mode=… serving=… nr=… rsrp=… nrRsrp=… neighbors=… dataRat=…`
- `core/telephony/NetJudge.kt`（新增，纯 Kotlin，可单测）：`classify()` / `carrierKey()` / `operatorKey()` / `belongsTo()`
- `core/sampling/SamplingController.kt`：SA/NSA 下单目标可命中「NR 服务小区 / 服务小区 / LTE 锚点」任一，RSRP 按命中对象取；`sampleIntervalMs` 范围放宽
- `ui/map/SingleMapScreen.kt`：`ratText`/`servingText` 按 `netMode` 渲染；SA 显示「5G SA · <NCI>（独立组网，无 LTE 锚点）」；邻区为空时追加 `neighborNote`
- `ui/map/BaiduMapCanvas.kt`、`ui/map/MapCanvas.kt`：轨迹分段着色（命中蓝 / 脱离灰）
- `ui/settings/SettingsScreen.kt`：「打点间隔」手动输入（`AlertDialog` + 0.2~600 秒校验）

## 四、真机验证证据（logcat `CellReader`）

```

nr=NR(5G)·460-00·NCI 5677244420(gNB 1386046-4) PCI 708 NR-ARFCN 504990 rsrp=-102 nrRsrp=-87 neighbors=0
```

修复后（PLMN 过滤 + 状态机）：
```

rsrp=-79 nrRsrp=-79 neighbors=0 dataRat=5G
```

→ SA 正确、服务小区就是 NR 的 NCI、无锚点、RSRP 与 SIM 行一致。

## 六、已知限制

- 5G SA 下邻区列表仍可能为 0：系统/芯片不提供，App 只解释原因，不伪造数据。
- 运营商过滤依赖「小区广播 PLMN + 运营商名」；漫游到境外或虚拟运营商认不出时会保留全部小区（宁可多显示，不误删）。
- 双卡时「服务小区」只反映当前数据卡；另一张卡的状态在 SIM 行展示。
- 空心点/灰色连线依赖 `onTarget`/`targetSeen` 判定，因此必须在创建任务时填对目标编号（`gNB-CID`、`NCI`、`ECI` 均可）。
