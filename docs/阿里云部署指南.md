## 三、从零部署主路径（systemd 方式）

以下为在同等规格新实例上复现当前实况的完整步骤。

### 3.1 前置准备

| 项 | 要求 |
| --- | --- |
| 实例规格 | 2 vCPU / 4GiB（ecs.e-c1m2.large）以上 |
| 操作系统 | Ubuntu 24.04 64 位（22.04 亦可，命令一致） |
| 安全组 | 入方向 TCP 22（限团队出口 IP）、TCP 8080（0.0.0.0/0 试点期）；443 启用 HTTPS 后再放行 |
| 本机工具 | workbench CLI（远程命令与文件上传，无需公网 SSH） |

### 3.2 安装运行时与目录初始化（服务器内执行）

```bash
sudo apt-get update
sudo apt-get install -y openjdk-21-jre-headless

sudo mkdir -p /opt/weilie/data

# 影像验真签名密钥：32 字节随机数，权限 600，生成后立即离机备份
head -c 32 /dev/urandom | sudo tee /opt/weilie/data/hmac.secret > /dev/null
sudo chmod 600 /opt/weilie/data/hmac.secret

sudo touch /var/log/weilie.log
```

> `hmac.secret` 生成后第一件事是备份到安全位置（如团队密码管理器/离线介质）。该文件丢失 = 已登记照片的验证码全部无法验签，且重生成会使新旧签名不一致。

### 3.3 上传制品（workbench CLI，本机执行）

```bash
# 上传 fatJar（-f 覆盖远端同名文件）
workbench upload weilie-server-all.jar /opt/weilie/weilie-server-all.jar -i i-0xieiymktekjfhe5b80q -r us-east-1 -f
```

### 3.4 systemd 单元（服务器内执行）

写入 `/etc/systemd/system/weilie.service`：

```ini
[Unit]
Description=Weilie Ktor cooperation & photo-verify backend
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
WorkingDirectory=/opt/weilie
Environment=WEILIE_DATA_DIR=/opt/weilie/data
ExecStart=/usr/bin/java -Xms64m -Xmx320m -jar /opt/weilie/weilie-server-all.jar
Restart=always
RestartSec=3
StandardOutput=append:/var/log/weilie.log
StandardError=append:/var/log/weilie.log

[Install]
WantedBy=multi-user.target
```

启动并设为开机自启：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now weilie.service
```

### 3.5 部署验证

```bash
# 本机或任意外网环境
curl http://47.89.181.85:8080/api/health
```

返回正常即部署成功。随后可依次抽查 `GET /api/photo/count`（应返回数字）与浏览器打开协同页确认 WebSocket 可用。

## 四、日常运维

### 4.1 重启服务（workbench CLI 口径）

```bash
workbench exec -i i-0xieiymktekjfhe5b80q -r us-east-1 --command "systemctl restart weilie.service"
```

> **注意**：`exec` 的 `--command` 是必填 flag，命令串必须放进该参数；位置参数形式会报错。

### 4.2 日志查看

```bash
# 追加式应用日志
workbench exec -i i-0xieiymktekjfhe5b80q -r us-east-1 --command "tail -n 100 /var/log/weilie.log"
# systemd 视角（含启动失败原因）
workbench exec -i i-0xieiymktekjfhe5b80q -r us-east-1 --command "journalctl -u weilie.service -n 100 --no-pager"
```

### 4.3 版本更新流程

1. 本地构建新 fatJar；
2. `workbench upload`（`-f` 覆盖）；
3. `workbench exec … --command "systemctl restart weilie.service"`；
4. `curl /api/health` 验证；重启后 `snapshot.json` 自动恢复房间状态，`photo-registry.jsonl` 与 `hmac.secret` 不受影响。

### 4.4 数据目录备份（建议每周）

```bash
workbench exec -i i-0xieiymktekjfhe5b80q -r us-east-1 --command "sudo tar czf /tmp/weilie-data-$(date +%F).tgz -C /opt/weilie/data . && ls -l /tmp/weilie-data-*"
```

备份产物至少异地留存一份；`hmac.secret` 单独再备（见 3.2 警示）。

## 五、docker compose 备选方案

> 当前线上**未使用**容器方案，systemd 主路径已满足试点需求。如后续需要容器化隔离（多服务混部、镜像化交付），按本节执行；`weilie/server` 仓库内已提供 `Dockerfile` 与 `docker-compose.yml`（8080 端口、`./data` 挂载卷、`restart: unless-stopped`、30 秒房间快照周期）。

```bash
# 安装 Docker 与 compose 插件（Ubuntu）
sudo apt-get update
sudo apt-get install -y ca-certificates curl gnupg
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | \
  sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] \
  https://download.docker.com/linux/ubuntu $(lsb_release -cs) stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin

# 启动（把 fatJar 与 compose 文件置于同一目录，data/ 挂载卷内同样放 hmac.secret 等三件套）
sudo docker compose up -d
sudo docker compose logs -f          # 跟随日志
sudo docker compose restart          # 重启
```

容器方案的验证与主路径一致（`/api/health`）；数据目录含义相同，注意容器内 `WEILIE_DATA_DIR` 与卷挂载路径对应。

## 六、内网穿透备选（frp）

无公网服务器/临时演示场景，可用 frp 把本机开发机的后端暴露到任一有公网 IP 的机器：

- **frps（公网侧）**：`frps.toml` 设 `bindPort = 7000`，`systemd` 或前台运行；
- **frpc（本机）**：`frpc.toml` 配置

```toml
serverAddr = "<frps公网IP>"
serverPort = 7000

[[proxies]]
name = "weilie"
type = "tcp"
localIP = "127.0.0.1"
localPort = 8080
remotePort = 8080
```

演示设备接入 `http://<frps公网IP>:8080` 即可。frp 链路不落地数据，演示结束即断开；正式采集与取证场景仍以 ECS 主路径为准。

## 九、常见问题

| 现象 | 排查 |
| --- | --- |
| `/api/health` 不通 | 先查安全组 8080 规则，再查 `systemctl status weilie.service` 与 `/var/log/weilie.log` |
| 服务反复重启 | `journalctl -u weilie.service -n 50`：多为 jar 路径/JDK 版本/内存参数问题；`-Xmx320m` 在 2 核 4G 上足够，勿在更小规格机器沿用 |
| 重启后房间丢失 | 确认 `WEILIE_DATA_DIR` 指向的目录存在且含 `snapshot.json`；快照在停止前最近一次写入 |
| 照片验真全部失败（签名无效） | `hmac.secret` 与登记时不一致（被重生成/换机）；恢复备份密钥后即恢复 |
| 单张照片验真失败（图片被修改） | 属预期行为：照片文件在登记后被改动即哈希不一致，这正是验真的设计目标 |
| 上传 jar 报错 | 确认 `-i` 实例 ID 与 `-r us-east-1` 匹配，`-f` 已加（覆盖远端文件） |
