## 摘要

在侦查办案、大型活动安保与应急处突中，确定目标手机所在基站的**真实覆盖范围**，是划定侦查圈、部署盘查力量的关键环节。但基层长期面临「三无」困境：无专业路测仪（数万至数十万元）、无基站工程参数（运营商内部资料）、无把粗略参数收敛为可用边界的方法。上级能提供的往往只是一个小区编号与「半径约 1 公里」的圆，落到城区就是数十万平方米的空泛范围。

本项目研制「围猎」系统：在**免 root、零专用设备、全自研**的约束下，把普通安卓手机变成测量终端、把多名民警变成传感器阵列，完成目标基站覆盖边界的多人在途协同实测。系统支持 ECI、NCI、LAC+CI、经纬度+半径四类上级参数的容错解析与一键取本机驻留基站；以公开 Telephony API 免 root 采集服务小区与邻区信号，并对双卡、5G SA/NSA、部分 ROM 不返回邻区等情况做了专门适配，可选接入 Shizuku 以 shell 身份读取系统完整小区列表补全邻区；打点前设精度与距离双重安检，以匀速模型卡尔曼滤波抑制 GPS 抖动；边界拟合由「飞点剔除 → 有效点门槛 → 凹包（Alpha Shape）→ 折线抽稀与内缩 → 置信度评估」构成，并提供「模拟实测区域」模式（沿轨迹按可调半径铺圆/方块）作为采样稀疏时的兜底；同时输出信号热力图、理论覆盖区（全向/扇形/距离环带）与理论∩实测叠加。取证侧内置水印相机（时间/地址/双卡蜂窝参数烧录）、SHA-256 + HMAC-SHA256 在线验真（8 位验证码与第三方可扫网页），并支持队友跨设备查看取证原图。协同侧以 WebSocket 房间实现队长划区（矩形/圈层/扇区/自由绘制）、分片围测、标点与导航、实时位置汇聚与半双工语音对讲。工程上完成一次彻底的界面重构（统一设计令牌、单一深色主题）与 33 个版本的快速迭代，当前客户端 94 个 Kotlin 文件 26,517 行、单元测试 25 类 188 例全部通过（188/188），服务端 11 个文件 2,380 行，已在阿里云 ECS 稳定运行。

**关键词**：基站覆盖测量；移动通信；协同定位；Alpha Shape 凹包；卡尔曼滤波；IDW 插值；等值线；取证水印；影像验真；Android

## 一、背景与需求分析

### 1.1 实战痛点：基层无高级装备条件下的覆盖定位难题

在侦查办案、大型活动安保、应急处突等场景中，确定目标手机所在基站的真实覆盖范围，是划定侦查范围、部署盘查力量、缩小搜捕圈的关键环节。该环节在基层长期存在「三无」困境：

1. **无装备**。专业路测仪（TEMS、QXDM 系列及配套软件）单价数万至数十万元，扫频仪更昂贵，一般只有省级或市级专门技术部门配备，县分局、派出所一级基本空白。
2. **无数据**。基站工程参数（方位角、下倾角、发射功率）属运营商内部资料，向基层开放受限；上级通常只能提供目标小区的标识参数与一个粗略覆盖半径——城区可能高达 1 公里，覆盖数万至数十万平方米。
3. **无方法**。面对 1 公里半径的参考圆，传统做法要么「撒网式」排查（人力消耗大、易暴露），要么凭经验目测（误差不可控、难以复盘）。缺少把「粗略参数」快速收敛为「可行动边界」的轻量技术手段。

与困境相对的是：每名民警随身携带的智能手机本身就是一台「移动信号测量终端」，持续接收所在与服务小区广播的小区标识与信号强度。**让普通手机成为测量仪器、让多名民警的走测样本汇聚为覆盖边界**，正是本作品要回答的问题。

### 1.2 需求定义

本作品把用户需求固化为一条完整作业链：

> **接收上级参数 → 建立测量任务 → 多人分片走测 → 覆盖边界收敛 → 置信度评估 → 现场取证 → 导出上报。**

各环节的硬约束：

- **输入**：参数格式不统一（ECI、NCI、LAC+CI、经纬度+半径，及其十六进制、带 MCC-MNC 前缀、全半角混杂等变体），必须「贴进来就能解析」；现场民警往往没有纸面编号，需要能一键读取本机当前驻留基站。
- **采集**：手机不 root、不拆机、不外接设备；现场可能信号不佳，采集须本地持久化、断点可用；GPS 在城区楼宇间易漂移，必须有可解释的质检规则。
- **分析**：样本是离散打点，必须输出连续边界，并给出「边界可信到什么程度」的量化结论；样本稀疏时也要有直观的可视化兜底。
- **协同**：4—12 人的围测小组需要实时共享位置、样本、标点与现场照片，队长需要能划分子区域、下发任务并掌握整体进度；现场噪声大、戴手套操作不便，需要语音通道。
- **取证**：边界结论需要现场照片佐证；照片要能经受「是否被修改、是否本人所拍」的质证；队友与指挥端应能直接查看拍摄的原图。
- **输出**：结果要能进入既有 GIS 流程（CSV/GeoJSON/KML），并支持带底图的成果图导出。

### 1.3 设计原则

1. **能落地**：所有功能以「民警单手可操作、弱网可用、夜间可读」为准绳；
2. **可解释**：算法输出必须能用人话解释（如「置信度低：只走了 6 个方向」）；
3. **可复核**：测量与取证数据append-only 落盘、可导出、可第三方核验；
4. **守边界**：只观测手机被动接收的广播信息，不做信令解码、锁频、测速、KPI 等超范围能力。

## 二、国内外现状与本作品定位

### 2.1 专业路测软件

以 TEMS Investigation、QXDM/QualiPoc、珠海世纪鼎利 Pilot 系列为代表的商用路测软件，是运营商网络优化的标准工具：支持全制式信令采集、层三解码、自动测试计划、KPI 统计与报告生成。但其定位与公安基层实战显著错位：

| 维度 | 专业路测软件 | 本作品「围猎」 |
|---|---|---|
| 目标用户 | 运营商网优工程师 | 基层办案民警 |
| 硬件要求 | 专用测试终端 / 扫频仪 / root 测试机 | 普通安卓手机，免 root |
| 价格 | 数万至数十万元 | 免费自研 |
| 使用门槛 | 需专业培训 | 向导式操作 + 普通/专家双模式 |
| 多人协同 | 无（单人单机） | 核心能力：分片围测、实时汇聚、语音对讲 |
| 输出形态 | 网优报告、KPI 图表 | 可行动的覆盖边界（GIS 可用） + 取证照片 |
| 合规属性 | 涉及信令解码等受控能力 | 主动规避敏感功能，纯物理层观测 |

### 2.2 众包与手机端测量工具

CellMapper、Network Cell Info 等应用证明「手机众包测量」技术可行，但其目标分别是全球基站数据库共建与信号地图展示，均未针对「给定目标小区、快速收敛覆盖边界、支撑围捕决策」建模；也缺乏多人实时协同、置信度量化与取证能力。

### 2.3 本作品的定位差异

本作品并非「简化版路测软件」，而是面向**单一任务（覆盖边界实测）、特定群体（无装备基层民警）、协同作业（多人分片围测）** 的轻量专用系统：功能上做减法（不做测速、KPI、测试计划、信令解码），协同与算法上做加法（分片调度、边界拟合、置信度量化、现场取证）。

## 三、系统设计

### 3.1 总体架构

系统采用「端—云」两层架构，端侧分五层：

- **采集层**（Android）：TelephonyManager 公开 API 采集服务小区与邻区（CI/NCI/PCI/ARFCN/RSRP/RSRQ/SINR），融合 GNSS 定位，秒级时戳打点，JSONL append-only 落盘；可选 Shizuku 通道以 shell 身份执行 `dumpsys telephony.registry` 补全邻区。
- **数据层**（Android）：会话级 `manifest.json + samples.jsonl`，天然满足「测量记录即证据」的追加写语义；照片按任务隔离存储。
- **算法层**（纯 JVM Kotlin，可单测）：坐标转换、飞点剔除、卡尔曼平滑、Alpha Shape 凹包、多边形缓冲与内缩、折线抽稀、IDW 热力网格、Marching Squares 等值线、距离场缓冲、置信度合成。
- **呈现层**（Jetpack Compose）：统一设计令牌（间距/圆角/发丝线/字阶）与单一深色主题；双模式信息呈现（普通/专家）；地图层经 `MapEngine` 抽象，百度 SDK 与 Canvas 兜底两条实现。
- **协同层**（服务端）：Kotlin Ktor 2.3.12 + WebSocket，内存房间 + JSON 快照持久化；反向代理/直连 HTTP；承载房间、验真登记、取证原图、基站库与健康检查。

一条样本的完整旅程：**传感器采集 → 双重安检 → 卡尔曼平滑 → 会话 JSONL 追加 → 拟合引擎增量触发 → 边界/热力/置信度更新 → 本机渲染 + WebSocket 广播队友 → 会话结束导出 CSV/GeoJSON/KML/成果图**。

## 四、关键技术与创新点

### 4.1 创新点一：四格式容错解析与「一键取本机基站」

实战参数「脏」得超乎想象：全角半角混杂、中英文标点混用、十六进制与十进制并存、有无制式标签、有无 MCC-MNC 前缀。`TaskInputParser` 对四类格式做统一容错：

1. **ECI**（LTE，28 bit）：`ECI 217546496`、裸十进制、`0x0CF7A40`、`0CF7A40H`、`460-00-217546496` 五种变体；
2. **NCI**（NR，最大 36 bit）：带标签与裸数字，超 28 bit 自动按 NCI 处理，超 36 bit 给出「请核对」警告；
3. **LAC+CI**（2G/3G）：`LAC 12345 CI 67890`、`12345-67890`、`LAC:12345,CI:67890`，并以「LAC ≤ 65535」等启发式消解破折号歧义；
4. **经纬度+半径**：`31.2304,121.4737,500m` 等，缺半径时给出「默认按 1000 m 展示参考圆」的白话提示。

解析前做 NFKC 归一化（全角转半角）与中文标点统一；解析后自动拆解 eNodeB/gNB 与 CID、给出十六进制对照，供民警与运营商侧核对。校验不通过时明确说明原因并禁止建任务，杜绝「脏参数」进入采集。

**一键取本机基站**：现场往往没有纸面编号。新建任务页可一键读取数据卡当前驻留小区——NR 制式填入 `NCI <36bit 编号>`，LTE 填入 `ECI <28bit 编号>`，并自动加入目标清单、选中、显示分解式与信号提示；读不到时明确提示检查插卡与权限，绝不写入伪参数。该功能把「建任务」从手工抄录两次校验，压缩为一次点击。

### 4.2 创新点二：免 root 多制式采集与 5G 双卡适配

采集仅依赖公开 API 即可获取服务小区与邻区的小区标识、频点与信号质量，配合 GNSS 完成时空打点；全程不 root、不反射、不使用隐藏 API。针对 Android 版本与 ROM 差异做了逐制式适配与字段降级：

- **双卡分卡采集**：按数据卡取小区，避免双卡数据串扰；并按 PLMN 对运营商做二次过滤，规避某些 ROM 的 `createForSubscriptionId` 混入他网小区的问题；
- **5G SA/NSA 判定**：`NetJudge` 依据服务小区制式、锚点关系与数据网络类型划分 SA/NSA/LTE/LEGACY；SA 下直接以 NR 为服务小区，NSA 下显示 5G 数据态并以 LTE 锚点补充说明；
- **邻区补全（可选 Shizuku）**：部分 ROM 的系统 API 只返回驻留小区。用户安装并授权 Shizuku 后，应用以 shell 身份执行 `dumpsys telephony.registry`，解析 `mCellInfo` 中的全部小区（含未注册邻区），每 2 秒刷新一次；NCI 为 36 位，解析时按 `Long` 处理避免溢出；未授权时自动回退系统 API，主区判定不依赖该通道；
- **编号语义**：36 位 NCI 按「gNB × 4096 + 12 位 CID」、28 位 ECI 按「eNodeB × 256 + 8 位 CID」分解，同一编号同时提供十进制、十六进制与分解式（如 `5677244420(1386046-4)`）三种展示。

### 4.3 创新点三：打点质检与轨迹平滑

GPS 在城区楼宇间的漂移会直接污染边界。系统在采样入口设置两道质检与一级平滑：

1. **精度安检**：定位精度半径 > 50 m 的样本丢弃，并以状态条提示「当前精度 168 m，已跳过」；门槛可在设置中调整；
2. **距离合并**：与上一成功点距离 < 1 m 的样本合并（更新信号均值），提示「距上个点 0.8 m 小于 1 m，已合并」；
3. **匀速模型卡尔曼滤波**（`TrackGate`）：对经纬度分别建立位置-速度状态与 2×2 协方差，按打点间隔预测、按测量噪声更新（过程噪声 q=1.6、测量噪声 r=1.0），连续偏离 3σ 时重捕获，兼顾抑制抖动与不丢真实移动。

打点间隔默认 1 秒，可在工具箱中切换 1/2/5 秒或手动输入 0.2—600 秒，兼顾精度与耗电。

### 4.4 创新点四（核心）：从「人到过哪」到「信号到得了哪」

覆盖边界不是简单的散点外包。系统把拟合拆成「三类点 → 飞点剔除 → 有效点门槛 → 凹包 → 抽稀内缩 → 置信度」的可解释流水线：

**（1）三类采样点。** 每个样本按目标命中情况分类：主区命中（连上目标小区）为实心点；邻区命中（邻区列表按 NCI/PCI+MCC/MNC 指纹匹配到目标）为按小区着色的实心点；脱离目标（既未连上也不在邻区）为空心点，只画轨迹、不参与成面。

**（2）飞点剔除（`TrackSanity`）。** 过滤非有限坐标、|纬度| > 85°、(0,0)、定位精度 > 120 m 的样本；再以坐标中位数为中心，剔除与中心距离 > 3 km 的离群点——即使单个坏点也无法把边界撑到城市尺度。

**（3）凹包成面（`AlphaShape`）。** 采用 Bowyer–Watson 三角剖分与自适应 α（α = max(用户参数, 2.2 × 平均最近邻距)）提取凹包，贴合街道走向与楼宇遮挡造成的凹陷，避免凸包把「没走过的街区」也算进覆盖。

**（4）抽稀与内缩。** Douglas–Peucker 抽稀去掉 GPS 抖动造成的锯齿；按定位精度对内点做边缘内缩与降权，把测量不确定度显式编码进几何。

**（5）模拟实测区域（`TrackBufferArea`）。** 采样稀疏或只走了一条街时，凹包会退化为细长条或无法成面。此时可切换「模拟实测区域」：以轨迹点为圆心铺可调半径（默认 30 m，5—200 m）的圆或方块，沿轨迹连成走廊。实现上不是逐点画圆再合并（会得到互不相连的多块），而是构造**到轨迹线段的距离场**，用 Marching Squares 在等值面上提取闭环——因此走廊连续、边界平滑，且只统计命中目标的点，脱离目标的轨迹不计入。

**（6）置信度评估。**

> 置信度 = 样本量因子 × 0.5 + 16 扇区方向覆盖度 × 0.5

样本量因子 = min(1, 有效样本数 / 120)；16 扇区方向覆盖度以质心为原点统计有效点落入的扇区比例，直接度量「围测是否留缺口」。得分 ≥ 70 且覆盖 ≥ 12/16 扇区为「高」，≥ 40 为「中」，否则「低」。模型把「采了多少」与「采得全不全」同时纳入，为指挥员提供可引用的量化依据。

**（7）双模式与双坐标。** 同一模块提供「高精度凹包」与「模拟实测区域」两种成面方式，全部结果同时输出米制局部坐标与 WGS-84 经纬度，供热力渲染、地图绘制与 GIS 导出。

### 4.5 创新点五：热力图、理论覆盖区与成果图

- **信号热力图**：对采样点做 IDW 反距离加权插值，生成 RSRP 连续场并以栅格图（`GroundOverlay`）叠加到地图；色带为强（蓝绿）—中（黄）—弱（红橙），阈值、网格间隔、扩散半径、透明度均可调。
- **理论覆盖区**：输入经纬度与可选方位角/距离，生成全向圆（无方位角）、120° 扇形（有方位角）或橙色距离环带（有距离），与实测边界对照，回答「理论应覆盖到哪、实测到哪」。
- **理论∩实测**：计算理论区与实测区的几何交集并以紫色叠加，直观显示「该覆盖却未测到」的盲区。
- **带底图成果图导出**：调用百度地图 `snapshot()` 获取当前底图位图，再用投影坐标把三类采样点、邻区彩色点、实测边界、理论区合成到图上，输出可直接用于汇报与存档的 PNG。

### 4.6 创新点六：多人协同的「划区—围测—汇聚」闭环

单人走一圈耗时长且易错过时机，系统将作业升级为多人协同：

### 4.7 创新点七：取证相机、影像验真与跨设备照片

**取证相机**：CameraX 全屏取景，拍照即烧录两段水印——大字时间/日期/星期/逆地理地址与可编辑备注；每张 SIM 卡逐卡列出运营商、制式频段、ARFCN、PCI、NCI/ECI（含分解式）、RSRP、SINR。取证类型分五类（普通取证、隐蔽摄像头、可疑摄像头、可疑设备、其他），地图上以不同 emoji 图标与配色区分。无定位时水印不再打印伪坐标，而是显示「GPS 定位中…」。

**跨设备查看**：服务端新增原图存储（`PhotoFiles`，单张上限 8 MB，验证码命名，先写临时文件再原子移动）。拍摄端登记后自动上传原图；队友点开照片标点时，若无本机记录则按验证码从服务器拉取原图与登记信息，详情页直接显示照片，并注明「照片由拍摄设备上传」。旧照片不会回溯同步，只有新拍照片具备该能力。

## 六、合规与伦理

本作品自立项起把合规作为与功能同等重要的约束：

1. **全自研**：全部代码原创，不复制、不反编译第三方应用源码/so/资源；仅把 CellularPro 的字段词典作为公开技术资料对照，并在同一测试机、同一小区以原版软件读数做对拍金标准——用其「产物」而非「本体」。
2. **权限最小化与透明**：仅申请定位、相机、电话状态（用于读取本机小区与双卡信息，运行时弹窗说明用途）、录音（按住对讲时才使用）、通知、网络等必要权限；不申请与功能无关的权限；Shizuku 为可选增强，需用户自行安装并明确授权，未授权自动回退。
3. **功能负面清单**：不做锁网锁频、测速、KPI 统计、测试计划（含自动呼叫）、信令事件解码——它们要么触碰运营商网络完整性，要么涉及受控信令信息。系统只观测手机被动接收的广播信息，不注入、不干扰、不解码任何网络信令。
4. **数据安全**：测量数据仅存本机会话文件与用户自建服务器，不接入第三方数据平台；地图 AK 用户自备；AI 调用走用户自配 key 并经白名单域守卫过滤；取证原图存储于自建服务器 `data/photos`，单张上限 8 MB。
5. **伦理与使用边界**：首启法律声明明确本工具仅供依法执行职务的人民警察及经授权的培训教学场景使用；测量对象为基站信号这一物理现象本身，不针对、不识别任何个人通信内容，不存储、不传输通话、短信与用户身份信息。
6. **第三方数据合规**：基站库数据来自 OpenCelliD（CC BY-SA 4.0），界面内标注来源与坐标精度（约百米量级），仅作参考图层。

### 6.1 取证可信性的边界论证

影像验真不承诺「照片绝对真实」，只回答「照片自登记起未被修改、确由某设备某时某地登记」。哈希锁定内容、HMAC 锁定登记行为、验证码与二维码供人复核；三项相互独立又互为印证。照片本体与个人身份信息不进入登记记录，签名密钥仅存于用户自建服务器本地（权限 600），不内置、不上传。照片内容是否摆拍，仍属办案人员职责，系统不越界代断。

## 七、研制过程中遇到的问题与解决方案（一问一答）

> 本章复盘研制期最典型的 15 个问题，均来自真机与模拟器实测，按「现象—定位—解决—验证」四段式记录；对应代码与版本见括号内标注。

### 问题 1：人走了，轨迹点却没跟上

**现象**：v0.6.0 真机走测时，地图上的轨迹点明显滞后于脚步，转向后要过两三秒才回正。
**定位**：GPS 每秒一次本身够用，问题出在平滑层——当时用的是纯位置卡尔曼，每帧对量测的增益只有约 0.2，位置被旧值拖住，速度信息完全没用上。
**解决**：整文件重写为匀速（CV）模型卡尔曼滤波，位置与速度两状态联动（`Axis{pos, vel, p00, p01, p11}`，过程噪声 q=1.6、量测噪声 r=1.0），并对 3σ 之外的量测做重捕获，避免急转弯被当成飞点（`core/fitting/TrackGates.kt`，v0.6.1）。
**验证**：同一路线 165 点会话复测，轨迹与步行路线贴合，转向无拖尾；单元测试固定 4 组场景回归。

### 问题 2：室内、树荫下 GPS 精度差，还会产生重复点

**现象**：刚进屋时精度掉到 168 m，轨迹瞬间跳到几百米外；原地站着不动，每秒都生成一个新点。
**定位**：系统给的是「观测值」，没有质量闸门；精度差与相邻点过近都会污染面积拟合。
**解决**：打点前做双重安检——精度超过阈值（默认 50 m）直接丢弃并提示「当前精度 168 m，已跳过」；与上一个成功点距离小于阈值（默认 1 m）则合并并提示「距上个点 0.8 m 小于 1 m，已合并」。两个阈值都在设置页可调（`core/fitting/TrackGates.kt` + `Route.PREF_GATE_*`，v0.5.1/v0.6.1）。
**验证**：真机室内外切换时提示文案与丢弃行为一致；室内走测不再出现跳点轨迹。

### 问题 3：手机卡是 5G，数据栏却只显示 LTE

**现象**：用户截图反馈「点展开之后还是 LTE」，主行写着 5G、展开只有一条 LTE 小区。
**定位**：NSA 组网下，Android 只把 LTE 锚点当作 registered 服务小区上报，NR 辅载波在另一条 CellInfo 里；早期实现只渲染了 serving。
**解决**：数据栏改为两行——第一行「5G NR · 运营商 频段 · NCI · PCI · RSRP」，第二行「锚点 LTE · …」；SA 场景不拼锚点行。数据层引入 `NetJudge` 区分 SA/NSA/LTE/LEGACY，并按数据卡取小区（`ui/map/MapDataBar.kt` + `core/telephony/NetJudge.kt`，v0.4.5/v0.8.0）。
**验证**：真机 5G SA 显示「中国移动 · 5G SA」且无锚点行；NSA 显示两行，用户确认。

### 问题 4：邻区数量恒为 0

**现象**：真机始终「附近还有 0 个基站」，而同一位置专业软件能看到多个邻区。
**定位**：HyperOS 等 ROM 在应用层过滤了未注册小区，`getAllCellInfo()` 只返回驻留小区；此外早期代码用 `ciHex` 取值，2G/3G 邻区没有十六进制会被整体丢弃。
**解决**：一是修正渲染口径（`ci` 缺失时退化为「PCI x」「制式 小区」）；二是提供 Shizuku 增强通道——用户自行安装并授权后，以 shell 身份执行 `dumpsys telephony.registry`，解析完整 CellInfo 列表，每 2 秒刷新并去重补入邻区；未授权自动回退系统 API（`core/telephony/ShizukuCells.kt` + `AndroidCellReader.kt`，v0.8.1/v0.12.4）。
**验证**：真机授权后「附近还有 6 个基站」；模拟器无 Shizuku 时正确显示「未安装」。

### 问题 5：Shizuku 里显示已授权，管理页却是空的

**现象**：设置页显示「已授权」，Shizuku 应用管理页「已请求或声明 Shizuku 的应用程序」为空，用户怀疑授权没生效。
**定位**：`Shizuku.checkSelfPermission()` 在库内做了静态缓存（javap 反编译可见 `permissionGranted` 静态字段），服务重启或授权被清后仍返回旧值；管理页列出应用依赖枚举已安装包，部分 ROM 的包可见性限制会让它显示为空。
**解决**：放弃只依赖该方法判断——新增服务诊断行（Shizuku 版本号、服务 UID：2000=adb/shell、0=root）、「重新申请授权」按钮，以及「最近一次读取 HH:mm:ss：N 条小区 · 邻区 M 条」诊断，读取失败时给出具体原因（超时/无 mCellInfo/解析 0 条）。说明文案同时标注「管理器列表为空属正常」（`ui/settings/SettingsScreen.kt`，v0.12.5/v0.12.6）。
**验证**：真机可看到服务版本与最近读取结果，据此判断链路是否真的通。

### 问题 6：进地图瞬间出现巨大的青色圆斑

**现象**：新建任务刚进地图时，当前位置被一个几十米半径的大圆覆盖，过一会儿自己变小；暂停再恢复也消失。
**定位**：圆点半径以「米」表达，需要按当前缩放换算像素；但地图刚加载时 `mapStatus.zoom` 为 0，`156543.03392×cos(lat)/2^z` 直接爆炸。渲染指纹里又没算 zoom，缩放落定后不会重绘，于是大圆一直留着。
**解决**：渲染器不再读地图自身状态，改由相机把 `camera.zoom + 1` 传入作为唯一尺度源，z<6 时兜底 16，并把 zoom 计入内容指纹；采样点随后改为固定像素 Marker 图标（主区 26 px、邻区 28 px、脱离 20 px 空心），彻底与缩放解耦（`ui/map/BaiduMapCanvas.kt`，v0.8.1/v0.9.0）。
**验证**：进图 0.9 秒内的连拍截图无巨点；缩放全程点位尺寸稳定。

### 问题 7：覆盖面积被一个飞点撑到城市尺度

**现象**：拟合出的凹包突然扩到几公里，置信度骤降。
**定位**：Alpha Shape 的 alpha 取「自适应值 = 2.2×平均最近邻距」，一个远离轨迹的飞点会把 alpha 拉大，凹包退化成凸包；拟合流水线本身也没有质量过滤。
**解决**：新增 `TrackSanity` 统一剔除飞点（非有限值、|lat|>85、(0,0)、精度>120 m，并按中位位置剔除 3 km 外样本）；拟合、热力、成面、导出全部先过这一层；Alpha Shape 的 alpha 加下限与上限（`core/fitting/TrackSanity.kt` + `AlphaShape.kt` + `CoverageFitter.kt`，v0.11.2）。
**验证**：注入 5 km 外飞点的回归用例，检出 bbox 仍小于 500 m，测试通过。

### 问题 8：模拟实测区域「乱铺」——脱离目标也算、多个命中块只画最大一块

**现象**：目标未命中、整条轨迹都是灰点，地图上仍铺出一圈绿色区域；另一台手机上两个相距较远的命中点只显示其中一块。
**定位**：模拟区域只做了飞点过滤、没做目标命中过滤；成面用「每个点画圆」再取最大环，间距大于直径时多块圆互不相连，只保留最大一块。
**解决**：只统计有效点（本区命中，或邻区命中且邻区 RSRP ≥ -110 dBm），少于 2 个点不出面；几何改为「到轨迹线段」的距离场（圆=欧氏、方=切比雪夫），沿轨迹连续铺开，再用 Marching Squares 取等值线（`core/fitting/AreaBuilder.kt` + `TrackBufferArea.kt`，v0.12.2）。
**验证**：新增 6 个用例（脱离段、邻区计入、弱邻区排除、全脱离返回空、单点返回空、AUTO 模式同样忽略脱离点）全部通过；真机未命中场景不再出现区域。

### 问题 9：热力图整屏一个颜色

**现象**：打开热力图后全屏青绿，看不出强弱分布。
**定位**：模拟器 RSRP 恒为 -44 dBm，IDW 插值后整片都是「强」，属于数据单一而非渲染错误；但边界外扩时确实可能画出无意义的色块。
**解决**：加 bbox 防御（只用有效点范围外扩一格），默认透明度从 150 降到 115，强/弱阈值与网格步长、扩散半径全部可调，并在面板上写明每个参数的作用（`ui/map/HeatOverlay.kt` + `MapLayersPanel.kt`，v0.5.0）。
**验证**：真机多点走测可看到蓝绿—黄—红的连续过渡；模拟器单一信号下判为预期。

### 问题 10：多人自由绘制时双指一碰地图就飘

**现象**：单指画范围正常，第二根手指落下后地图开始漂移，且无法缩放。
**定位**：双指位移逐帧喂给相机的 `panBy`，而该换算基于 256 px 瓦片的「米/像素」理论值、未含屏幕密度（真机 2.6 倍），误差逐帧累加；绘制态又禁用了缩放手势，没有自己实现捏合。
**解决**：改为「起点锚定」——双指落下瞬间快照地图中心与缩放，移动时按投影实测的米/像素一次性换算（分别取两轴），捏合用 `log2(当前指距/起始指距)` 叠加到起始缩放，手势结束再回写相机；单指仍只负责落点（`ui/map/BaiduMapCanvas.kt`，v0.11.1）。
**验证**：真机双指拖动与缩放正常、抬手不漂；单指画点不受影响。

### 问题 11：窄屏上图层面板压住顶部与底部按钮

**现象**：队友的 360 dp 宽手机上，图层面板压住房间条、成员头像和底部「标记/拍照」，右缘还露出一块被裁的开关。
**定位**：面板用固定 top 偏移，没考虑顶栏高度；同屏还有右侧悬浮钮与底部操作栏争夺空间。
**解决**：测量顶栏实际高度（`onGloballyPositioned`）后动态定位面板，最大高度按「屏高 − 顶栏 − 200 dp」收敛，面板打开时自动收起右侧按钮、聊天浮层与底部操作栏，并提升面板 zIndex（`ui/team/TeamRoomScreen.kt`，v0.13.0）。
**验证**：density 3.5、1080×2400 真机截图确认无重叠。

### 问题 12：队友点开照片提示「未找到该标点的取证记录」

**现象**：A 手机拍照，B 手机点标点只看到「记录可能已被删除或来自其他设备」。
**定位**：协议里只传了 `photoId`，客户端又只查本机照片库，跨设备必然查不到；服务端只登记哈希与签名，不存原图。
**解决**：协议增加 `photoCode`，拍照端登记后把验证码随标点广播；服务端新增原图存储（`data/photos`，单张上限 8 MB）与上传/下载接口；详情页在无本机记录时按验证码拉取登记信息与原图，仍未上传则明确提示「拍摄设备未上传原图」（v0.13.0）。
**验证**：curl 端到端：登记 → 上传 303,543 字节 → 下载字节数与 SHA-256 完全一致；双机待复测。

### 问题 13：语音对讲既要低延迟又要省流量

**现象**：早期方案考虑文件式录音上传，延迟数秒，无法用于现场协同。
**解决**：改为半双工「按住说话」——16 kHz 单声道 PCM，每 100 ms 一帧（3,200 字节），base64 后经 WebSocket 转发，服务端只做房间内广播、不落库，端到端约 200—400 ms，带宽约 43 KB/s，2—6 人房间移动网络可承受；另加录制权限按需申请与「X 正在讲话」提示（`core/audio/VoiceTalk.kt` + `RoomClient`/`RoomWs`，v0.13.0）。
**验证**：模拟器与真机界面联调通过；协议编解码单元测试 5 例覆盖往返与旧消息兼容。

### 问题 14：室外单手操作、强光下看不清屏幕

**现象**：现场民警戴手套、单手持机、阳光直射，既要看轨迹又要判断是否到达目标。
**解决**：一是工具箱重排为 5 列×2 行一屏放下十个工具；二是静默跟踪模式——主区命中每 1 秒短震、邻区命中每 0.3 秒短震、完全检测不到则持续震动，直到恢复或手动关闭；全程不发声、不亮屏，状态写入日志，提供开关与通知栏两个停止入口（`core/tracking/SilentTrackLogic.kt` + `service/SilentTrackService.kt`，v0.5.0）。
**验证**：真机震动节奏与三种状态一一对应；退出服务后立即停止。

### 问题 15：取证照片如何证明「没被改过」

**现象**：现场照片在流转中可能被质疑真实性、时间地点也可能被质疑。
**解决**：拍照即烧录双段水印（时间/日期/星期/逆地理地址/备注 + 逐卡蜂窝数据），照片 SHA-256 上传登记换取 8 位验证码，服务端用 HMAC-SHA256 对登记记录签名，任何人可用验证码在网页或 App 内做三项校验（哈希、签名、登记时间），并支持原图上传后逐字节比对（v0.4.x—v0.13.0）。
**验证**：单元测试覆盖哈希、签名、篡改与缺字段场景；网页验真页与 App 内结果一致。

## 八、结论与展望

「围猎」以「普通手机即测量终端、多名民警即传感器阵列」为核心思想，在免 root、零专用装备、全自研、权限最小化的约束下，打通了「参数解析 → 多人分片走测 → 质检与平滑 → 凹包/模拟区域成面 → 置信度评估 → 现场取证与验真 → 协同与语音 → GIS 导出」的完整闭环。主要贡献：

1. 提出并实现面向公安实战的**多源融合覆盖边界拟合流水线**（三类点 → 飞点剔除 → 凹包 → 抽稀内缩 → 双因子置信度），并用「模拟实测区域」解决稀疏采样与条带走测的兜底问题；
2. 设计**16 扇区方向覆盖度**这一直接度量围测完整性的指标，使其与多人协同形成正反馈；
3. 以**四格式容错解析 + 一键取本机基站**消除参数壁垒，以**打点双重安检 + 卡尔曼滤波**保证数据质量，以**可解释的白话提示**消除使用门槛；
4. 设计并上线**影像验真**（SHA-256 登记 + HMAC 签名 + 二维码网页核验 + 跨设备原图），使取证照片具备第三方可独立复核的可信性；
5. 完成**协同作业平台化**（房间、划区、自由绘制、标点导航、跨设备照片、半双工语音），并交付 33 个可回归版本与 188 个单元测试作为工程可信度支撑。

后续工作：其一，扩大机型矩阵并系统标定各品牌 CellInfo 字段差异；其二，引入扇区方位角先验与地形修正，提升山区边界精度；其三，接入可信时间戳/公证存证通道，增强证据链的司法可采性；其四，标准化对接指挥调度系统（GeoJSON 服务化）；其五，在培训模式基础上沉淀实战案例库与考核题库，反哺公安教育训练。
