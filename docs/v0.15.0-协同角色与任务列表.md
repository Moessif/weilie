# v0.15.0：队长/队员双向转让 · 区域归属着色 · 任务列表 · 服务端完成度

## 一、协议 v1.2（客户端 + 服务端同步修改）
| 新增 | 作用 |
|---|---|
| `promoteRequest` | 队员申请接任队长，服务端只转发给现任队长 |
| `promoteDecline` | 队长拒绝申请，服务端转发给申请人 |
| `zoneDelete` | 删除任务区（创建者本人或现任队长） |
| `Zone.id` | 服务端分配稳定 id，删除与统计以它为准 |
| `ZoneStat` + `State.zoneStats` | 服务端按 20m 网格算出的区域覆盖率 |

服务端 `ZoneCoverage.kt`：圆区按半径、多边形按射线法，统计「网格中心在区内且该网格有采样点」的比例；
每攒 10 个采样点重算一次并广播 state（不做逐点广播）。

## 二、客户端
### 角色
- **实时角色**：`myRole` 取服务端 `state.members`，不再用入场时的 `lastRole` 决定权限；
- **采集跟角色走**：`LaunchedEffect(myRole)` 里按 `myRole != OBSERVER` 启停采集与前台服务，转让队长后无需退出重进；
- **角色回写**：角色变化即写 `AppGraph.lastRole`，重进房间用最新身份握手；
- **观战排除**：转让列表过滤 `OBSERVER`，观战不参与指挥链；
- **队员申请接任**：任务面板新增「申请接任队长」，队长端弹「同意 / 拒绝」。

### 区域与任务
- **按队长着色**：`ZoneStyle` 用 `zone.by` 哈希到 8 色调色板，两套地图引擎（Canvas / 百度）都按归属着色；
- **任务列表**（底部抽屉）：全部 / 现任 / 往届 / 我负责 四个筛选；
  每项显示区域名、归属队长、负责人、状态（未开始/进行中/已完成）、覆盖率百分比；
- **删除**：队长可删任意区域，创建者可删自己的区域，二次确认；
- **历史保留**：转让队长不会清空 `zones`，老区域仍在列表与地图上（服务端原逻辑保留，加了系统提示）。

## 三、部署顺序（重要）
1. **先升级服务端**：新客户端会发送 `promoteRequest` / `zoneDelete`，旧服务端反序列化未知类型会断开连接；
2. 再发布客户端；
3. 老客户端连新服务端：只多发一个空 `id` 字段，`zoneStats` 被忽略，行为不变。
