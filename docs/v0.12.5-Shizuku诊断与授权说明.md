# v0.12.5 — Shizuku 诊断行 + 授权状态说明

> 版本：`versionCode 31` / `versionName 0.12.5`  
> 背景：真机上围猎显示「邻区增强（Shizuku）· 已授权」，但 Shizuku 自己的「应用管理」页为空
> （「已请求或声明 Shizuku 的应用程序将显示在此处」），用户怀疑授权没生效。

## 一、结论先说

**「Shizuku 管理器里看不到围猎」不等于没授权。** 两件事走的是不同链路：

| 链路 | 依赖 | 表现 |
| --- | --- | --- |
| 授权本身 | `Shizuku.requestPermission()` → Shizuku 服务端按 uid 记账 → `Shizuku.checkSelfPermission() == GRANTED` | 围猎显示「已授权」，且能创建 shell 进程 |
| Shizuku 管理器「应用管理」列表 | Shizuku App 自己枚举**已安装应用**（`QUERY_ALL_PACKAGES` / ROM 的「应用列表」权限） | 部分 ROM（HyperOS/MIUI 等）限制应用列表访问，列表为空 |

所以判断授权是否真的生效，唯一可靠的标准是**能不能读到小区**——这也是 v0.12.5 新增诊断行的原因。

## 二、v0.12.5 新增：设置页诊断行

「设置 → 邻区增强（Shizuku）」授权后多一行实时结果：

```
最近读取 20:31:12：12 条小区 · 邻区 9 条
```

- 进入设置页、或点「刷新状态」时，会**真执行一次** `dumpsys telephony.registry` 并解析；
- 显示：读取时间、`mCellInfo` 解析出的总条数、其中**未注册（邻区）**条数；
- 失败时显示原因（红字 `WColors.Warning`）：
  - `未授权` — Shizuku binder 权限没拿到；
  - `无法创建 shell 进程` — Shizuku 服务异常/版本不匹配；
  - `命令超时` — 4 秒内没跑完；
  - `输出里没有 mCellInfo` — 系统 dumpsys 不再输出小区段（需按 ROM 适配解析）；
  - `mCellInfo 存在但解析为 0 条` — 输出格式与解析器不匹配（把这行截图发我即可定位）。

同时补了一句说明：「部分 ROM 限制应用列表权限，Shizuku 管理器里不显示围猎属正常，以本页状态和下方读取结果为准。」

## 三、实现

`core/telephony/ShizukuCells.kt`：

- 新增 `data class LastRead(atEpochMs, cellCount, neighborCount, hasCellInfoTag, rawChars, error)`
  与 `@Volatile var lastRead`；
- `readRegistry()` 所有出口（未授权 / 建进程失败 / 超时 / 异常 / 解析为 0）都会写入诊断，
  成功时记录总条数与邻区条数；
- `parseDump()` 仍是纯函数，测试不变。

`ui/settings/SettingsScreen.kt`：

- 新增 `LaunchedEffect(shizukuGranted, shizukuTick)` → `withContext(Dispatchers.IO) { ShizukuCells.readRegistry() }`，
  结果反射到 `shizukuDiag`（不轮询，进页面/点刷新时读一次，避免设置页后台常驻）；
- 诊断行用 `labelSmall`，出错时用 `WColors.Warning`。
