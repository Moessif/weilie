# v0.12.6 — 「已授权」但 Shizuku 侧显示 0 个应用：重新申请授权 + 服务诊断

> 版本：`versionCode 32` / `versionName 0.12.6`  
> 反馈：围猎显示「邻区增强（Shizuku）· 已授权」，但 Shizuku 主界面「已授权 0 个应用」、
> 应用管理页空白（「已请求或声明 Shizuku 的应用程序将显示在此处」）。

## 一、为什么会这样（两个独立事实）

1. **Shizuku 侧确实没登记围猎**：它的「已授权 N 个应用」来自 Shizuku App 自己的授权表，
   显示 0 就是没登记。而围猎的「已授权」来自 `Shizuku.checkSelfPermission()`
   —— **这个 API 在客户端有一个静态缓存 `permissionGranted`**：
   一旦某次返回 GRANTED，之后同一进程内不再向服务端确认。
   所以「重启过 Shizuku 服务 / 授权表被清空」时，围猎仍可能显示旧结论。
2. **Shizuku 的授权弹窗需要 Shizuku App 能弹 Activity**：部分 ROM（HyperOS/MIUI）默认禁止
   应用后台弹出界面，若 Shizuku 被限制，`requestPermission()` 请求就「静默消失」，
   围猎侧看不到回调、Shizuku 侧也不出现记录。

## 二、v0.12.6 做了什么

设置 → 邻区增强（Shizuku）新增两处：

| 新增 | 作用 |
| --- | --- |
| `Shizuku 服务 v13 · uid 2000` | 显示 binder 实际连到的服务版本与运行身份（2000 = adb/shell，0 = root）；连错实例/版本过低一眼可见 |
| 「重新申请授权」按钮 | 授权状态可疑时随时重发请求；成功发送会 toast「已向 Shizuku 重新申请，请在弹窗里点允许」 |
| 读取诊断行（v0.12.5 已有） | `最近读取 20:31:12：12 条小区 · 邻区 9 条` 或失败原因；这是授权是否真的生效的唯一硬证据 |

## 三、用户操作步骤（真机）

1. 安装 v0.12.6；
2. **强制停止围猎**（设置 → 应用 → 围猎 → 强行停止），清掉客户端里的 `permissionGranted` 缓存；
3. 打开围猎 → 设置 → 邻区增强（Shizuku）→ 点 **「重新申请授权」**；
4. 此时**应当弹出 Shizuku 的授权对话框**（类似「围猎 请求使用 Shizuku」）→ 点允许；
5. 回到 Shizuku 主界面，「已授权」应变成 **1 个应用**；围猎里诊断行应出现 `N 条小区 · 邻区 M 条`。

如果第 4 步**没有弹窗**，按顺序检查：

- Shizuku 主界面显示「Shizuku 正在运行」且版本 ≥ 13（截图是 13.5，满足）；
- 给 Shizuku 打开 **「后台弹出界面」/「显示在其他应用上层」** 权限（HyperOS：应用设置 → Shizuku → 权限管理 → 显示在其他应用上层；部分版本叫「后台弹出界面」）；
- Shizuku 用无线调试启动的，手机重启后需重新「启动」服务，否则围猎会显示「服务未运行」。
