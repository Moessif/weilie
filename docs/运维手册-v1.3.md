# 运维手册 v1.3

## 一、日常命令

```bash
sudo systemctl status weilie --no-pager
sudo systemctl restart weilie
sudo journalctl -u weilie -n 200 --no-pager
sudo tail -f /var/log/weilie.log
curl -s http://127.0.0.1:8080/api/health
curl -s http://127.0.0.1:8080/metrics | grep -E "rooms|online|rate_limited"
curl -s http://127.0.0.1:8080/api/rooms | head -c 800
```

## 二、数据目录

```
/opt/weilie/data/
├─ hmac.secret              # 影像验签密钥（600，必须备份）
├─ photo-registry.jsonl     # 照片登记（追加写）
├─ snapshot.json            # 房间快照（30s 一次，原子替换）
├─ photos/<code>.jpg        # 取证原图（最大 8MB/张）
├─ cells/                   # 基站库瓦片缓存
├─ audit.jsonl              # v1.3 审计日志（>64MB 滚动 .1）
└─ rooms/<roomId>/samples.jsonl  # v1.3 采样落盘（>64MB 滚动 .1）
```

### 备份（建议每天）

```bash
sudo tar czf /opt/weilie/backup-$(date +%Y%m%d).tgz -C /opt/weilie data
# 拉回本地保存；至少保留 7 天
```

优先备份顺序：`hmac.secret` → `photo-registry.jsonl` → `snapshot.json` → `audit.jsonl` → `rooms/` → `photos/`。

### 恢复

```bash
sudo systemctl stop weilie
sudo mv /opt/weilie/data /opt/weilie/data.old
sudo tar xzf backup-YYYYMMDD.tgz -C /opt/weilie
sudo chown -R root:root /opt/weilie/data
sudo systemctl start weilie
```

## 三、/metrics 指标

| 指标 | 含义 | 异常判断 |
|---|---|---|
| `weilie_rooms` | 当前房间数 | 持续上涨且不回落 → TTL/清理异常 |
| `weilie_online_members` | 在线成员数 | 掉到 0 但 App 显示已连接 → WS 异常 |
| `weilie_ws_connections` | 累计连接数 | 突增 → 可能有重连风暴 |
| `weilie_ws_messages` | 累计消息数 | 突增 → 检查限流日志 |
| `weilie_samples` | 累计采样点 | 应与走测规模匹配 |
| `weilie_photos_uploaded` | 照片上传数 | — |
| `weilie_rate_limited` | 被限流次数 | 持续增长 → 阈值过严或有人刷 |
| `weilie_exports` | 导出次数 | — |
| `weilie_errors` | 内部错误 | >0 需查日志 |
| `weilie_uptime_seconds` | 运行时长 | 频繁归零 → 进程在重启 |

## 五、审计日志

文件：`data/audit.jsonl`，每行一个 JSON：

```json
{"ts":1731600000000,"action":"promote","roomId":"df9ee158fe5f","userId":"u-1001","detail":{"to":"u-1002","toName":"张三"}}
```

| action | 含义 |
|---|---|
| `room_create` | 创建房间（含 IP、房间名） |
| `join` / `leave` | 成员进/出房间（含角色） |
| `promote` | 队长转让 |
| `promote_request` / `promote_decline` | 接任申请 / 拒绝 |
| `zone` / `zone_delete` | 任务区下发 / 软删除 |
| `marker` / `marker_delete` | 标点新增 / 删除 |
| `room_close` / `room_ttl` | 关闭房间 / TTL 回收 |
| `export` | 服务端导出（格式、采样数） |

查询示例：

```bash
grep '"action":"promote"' /opt/weilie/data/audit.jsonl | tail -20
grep '"roomId":"df9ee158fe5f"' /opt/weilie/data/audit.jsonl | tail -50
```

> 审计含 userId 与操作记录，属敏感数据；权限按取证要求管理，不要随意外发。

## 六、服务端导出

```bash
ROOM=df9ee158fe5f
CODE=332475
curl -o room.geojson "http://47.89.181.85:8080/api/teams/$ROOM/export?code=$CODE&format=geojson"
curl -o room.kml     "http://47.89.181.85:8080/api/teams/$ROOM/export?code=$CODE&format=kml"
curl -o samples.csv  "http://47.89.181.85:8080/api/teams/$ROOM/export?code=$CODE&format=csv"
```

- `geojson`：区域（多边形/圆转 64 边形）、标点、轨迹 LineString；
- `kml`：可直接导入 Google Earth/奥维；
- `csv`：`userId,ts,lat,lon,rsrp,onTarget`。

鉴权：`code` 必须是该房间的 6 位队伍码；错码返回 403。

## 七、房间生命周期

- 关闭：`POST /api/teams/{roomId}/close?code=XXXXXX`（管理员/队长均可，凭码）；
- TTL：无活动超过 `WEILIE_ROOM_TTL_DAYS`（默认 7 天）自动回收，每 10 分钟巡检一次；
- 回收会同时删除 `data/rooms/<roomId>/` 与内存态，`audit.jsonl` 保留记录。

## 八、故障排查

| 现象 | 排查 |
|---|---|
| `/api/health` 503/超时 | `systemctl status weilie`、`journalctl -n 100`、端口 `ss -lntp | grep 8080` |
| App 建房转圈 | 手机能否 `curl /api/health`；安全组 8080；服务端日志有无 `room_create` |
| 房间进不去 | 队伍码是否正确；`/api/rooms` 里是否有该房间；日志 `拒绝入房` |
| 覆盖率不涨 | 负责人是否在采样（`sampleCount`）；`data/rooms/<id>/samples.jsonl` 是否增长；`zoneStats` 每 10 点刷新 |
| 重启后覆盖率归零 | 检查 `rooms/<id>/samples.jsonl` 是否存在、`WEILIE_DATA_DIR` 是否一致 |
| 大量限流 | `/metrics` 看 `weilie_rate_limited`；确认不是压测/重连风暴 |
| 照片打不开 | `data/photos/<code>.jpg` 是否存在；`/api/photo/file?code=` 是否 429 |
| 服务重启后房间没了 | `snapshot.json` 是否可读（JSON 坏了会空库启动，日志有“快照恢复失败”） |
