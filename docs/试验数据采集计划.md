# 「围猎」试验数据采集计划（初稿 v0.1）

> **文档用途**：规定研究报告第 5～6 章所需试验数据的场景选择、路线设计、样本量目标、人员分工、质量控制与对拍验证方法，确保采集成果能支撑覆盖边界重建算法的验证与申报材料要求。
> **口径声明**：本文所列全部数值指标均为**目标值**（用于质量控制与验收判定），非实测值；实测结果在试验完成后以【待试验后填写】方式回填。不编造任何数据。

---

## 一、目标与指标定义

### 1.1 采集总目标
- 为三种典型场景（城市/郊区/室内）各获得一份可用于覆盖边界重建的达标数据集；
- 为算法验证获得可对拍、可复核的重复采集数据；
- 为报告第 6 章性能指标（打点成功率、丢帧率等）提供原始记录。

### 1.2 核心指标（目标值）

| 指标 | 定义 | 目标值 | 判定方式 |
| --- | --- | --- | --- |
| 单场景样本量 | 单场景单运营商有效打点帧总数 | **≥200 点** | 导出 CSV 行数（有效帧口径） |
| 方向覆盖度 | 有达标样本的方位扇区数/16 | **≥12/16 扇区** | 系统内置 16 扇区统计 |
| GPS 精度 | 单帧水平定位精度 | **≤20m 方记有效帧**，有效帧占比目标 ≥90% | accuracyM 字段过滤 |
| 采样连续性 | 打点中断 | 单次中断 ≤30s，中断次数每轮 ≤5 次 | tsEpochMs 差分检查 |
| RSRP 阈值 | 达标覆盖判定门限 | 【待填：建议 -105dBm 或与业务方商定】 | rsrp 字段过滤 |
| 重复采集重合度 | 两次独立采集边界重合程度 | 目标：重合度高且偏差可解释（IoU 方法【待填：与报告 5.4 统一定义】） | 边界叠加比对 |
| 对拍一致性 | 与运营商 App 信号格定性一致 | 无方向性矛盾 | 现场记录表 |

> 说明：RSRP 阈值一经确定，全部场景、全部算法分析保持一致，不得中途更换。

## 二、试点选址标准

### 2.1 城市场景
| 项 | 标准 |
| --- | --- |
| 环境特征 | 密集城区，建筑平均高度≥6 层，路网呈网格状 |
| 目标基站 | 市区宏站，站型与频段【待填：以实际可测基站为准】 |
| 干扰要求 | 周边同频邻区≥3 个（检验多小区重叠下算法表现） |
| 交通方式 | 步行 + 非机动车为主（低速，样本空间密度高） |
| 安全要求 | 人员不进入机动车道采集；避开早晚高峰 |

### 2.2 郊区场景
| 项 | 标准 |
| --- | --- |
| 环境特征 | 城郊开阔地带，低层建筑，遮挡少 |
| 目标基站 | 郊区宏站，预期覆盖半径较大【待填：站址信息】 |
| 干扰要求 | 邻区稀疏，服务小区主导明显 |
| 交通方式 | 机动车绕行（车内采集，注意固定手机、外接供电） |
| 安全要求 | 采集中司机专职驾驶；路线避开施工路段 |

### 2.3 室内场景
| 项 | 标准 |
| --- | --- |
| 环境特征 | 大型公共建筑（如教学楼/办公楼）1～2 个完整楼层 |
| 目标基站 | 室内分布系统（室分站）或穿透覆盖的室外站【待填：以踏勘为准】 |
| 路线要求 | 楼层内走廊环绕 + 电梯厅/楼梯间驻留点 |
| 特殊注意 | 记录进出楼层时间，便于事后轨迹与楼层对应 |

### 2.4 选址通用要求
- 每场景确定 1 个主选、1 个备选目标小区；小区参数（ECI/NCI/LAC+CI/经纬度+半径）由踏勘提前取得，用于验证四种输入格式解析；
- 踏勘记录表见附录 A。

## 三、采集路线设计

### 3.1 路线三要素：绕圈 + 横穿 + 定点
| 路线类型 | 目的 | 设计要点 |
| --- | --- | --- |
| **绕圈** | 沿预期覆盖边缘环绕，刻画边界轮廓，提升 16 扇区方向覆盖度 | 以基站为圆心、按预估半径的 0.5/0.75/1.0 倍分三圈；每圈间距均匀 |
| **横穿** | 穿过覆盖区中心，标定内外 RSRP 梯度，验证等值线内插 | 至少 2 条近似正交的穿越线，慢速匀速通过 |
| **定点** | 在特征位置驻留采样，获取稳定 RSRP 参考点 | 每场景≥5 个定点，每点驻留≥60s（含 1 个弱覆盖点） |

### 3.2 路线执行规则
- 绕圈顺序：外圈→中圈→内圈；遇信号跌出目标小区（targetSeen=0）不要立即折返，继续前进 30～50s 观察是否重选；
- 横穿速度：步行≤1.5m/s；车速≤40km/h，保证空间采样密度；
- 每轮采集起止：进入预定路线前 60s 开始打点，结束后继续 60s，留出边界余量；
- 方向覆盖度不足 12/16 时，针对缺失扇区补绕一圈（补采轮）。

## 四、人员分工（标准编组：2 手机 + 1 记录员）

| 角色 | 人数 | 装备 | 职责 |
| --- | --- | --- | --- |
| 采集员 A | 1 | 手机①（运营商 X【待填】，外接电源、车载支架） | 沿既定路线采集；保持 App 前台运行 |
| 采集员 B | 1 | 手机②（运营商 Y【待填】，同上） | 同路线同步采集（双运营商对照）；兼安全观察员 |
| 记录员 | 1 | 纸质/平板记录表 | 填写现场记录表：起止时间、路线偏移、异常事件（重选/掉话/信号突变）、对拍截图编号 |

- 每轮采集前统一对时（以同一授时源为准）；两部手机打点起始时间差目标 ≤10s；
- 条件允许时增加第 4 人负责照片拍摄（现场环境 + 对拍证据），可由记录员兼任。

## 五、采集操作规程

1. **采集前（前一日）**：确认手机电量≥90%、存储≥1GB、GPS 定位正常；导入目标基站参数（每次轮换使用一种输入格式：第 1 轮 ECI、第 2 轮 NCI、第 3 轮 LAC+CI、第 4 轮经纬度+半径，顺带验证四格式解析）；
2. **到场准备**：开启飞行模式再关闭一次以重置网络状态（可选动作，记录表中注明）；启动 App，确认打点帧率 1Hz 正常、GPS 精度≤20m；
3. **采集执行**：按路线三要素推进；记录员同步填写现场记录表；异常事件即时标注时间点；
4. **采集结束**：停止打点，现场核对样本数与方向覆盖度（App 内置统计）；不足目标立即补采；
5. **当日归档**：导出 CSV 原始文件，按第九节命名规范归档，记录员核对文件与记录表一致。

## 六、质量检查清单

### 6.1 采集前检查
- [ ] 目标基站参数已导入且解析正确（App 显示的目标小区标识与踏勘一致）；
- [ ] 两部手机分别为不同运营商；
- [ ] 电量/存储/定位达标；对时完成；
- [ ] 路线已导入或打印，记录表模板已备。

### 6.2 采集中检查（每 10 分钟一次）
- [ ] App 仍在前台、打点未中断；
- [ ] GPS 精度≤20m（精度变差时段在记录表标注）；
- [ ] targetSeen 命中状态与路线预期一致（未提前丢失目标）；
- [ ] 记录表时间点与打点时间同步。

### 6.3 采集后检查
- [ ] 有效帧数≥200（单场景单运营商目标值）；
- [ ] 方向覆盖度≥12/16；
- [ ] 采样连续性：无 >30s 断档（或断档均有记录表说明）；
- [ ] CSV 文件可正常导出打开，22 列完整；
- [ ] 现场照片/对拍截图已按编号归档。

> 任一硬性项不达标 → 当日安排补采；两轮补采仍不达标的场景，在数据说明中如实记录偏差原因。

## 七、对拍验证方法

### 7.1 与运营商 App 信号格对比（定性对拍）
- 方法：采集过程中，在≥5 个定点位置，同时记录系统测得 servingRsrp 与运营商官方 App（或系统设置内信号格数）显示格数；
- 判定：两者反映的强弱趋势应一致（格数高↔RSRP 高）；出现方向性矛盾时记录机型、系统版本与现场环境，作为 9.2 节局限性素材；
- 注意：信号格数是厂商映射结果，仅作趋势对拍，**不做数值等换**。

### 7.2 两次独立采集重合度（定量对拍）
- 方法：同一目标小区、同一路线，由**不同人员、不同日期**各采集一轮（间隔≥2 天，天气类型记录在案）；
- 分析：分别重建边界后叠加比对，计算重合度指标（建议 IoU 或面积交并比，方法定义【待填：与报告 5.4 统一】）；
- 判定：重合度未达预期时，分析差异来源（时段话务、天气、路线偏差、终端差异），如实写入报告 6.5 节；
- 该项同时用于检验置信度分档的合理性（低置信度区域是否恰为两次采集差异大的区域）。

### 7.3 对拍证据留存
- 每次对拍截图/照片以 `DUIPAI-<日期>-<地点>-<序号>` 命名，记录表登记编号，与数据集一并归档。

## 八、数据整理与归档规范

### 8.1 文件命名
- 原始数据：`RAW-<场景>-<运营商>-<YYYYMMDD>-<轮次>.csv`，如 `RAW-城市-X-20261208-R1.csv`；
- 现场记录表：`LOG-<场景>-<YYYYMMDD>-<轮次>.pdf`（或扫描件）。

### 8.2 目录结构
```
试验数据/
├── 城市/
├── 郊区/
├── 室内/
├── 对拍/
│   ├── 运营商信号格/
│   └── 重复采集/
└── 数据说明.pdf（汇总各数据集的设备、时段、天气、有效帧口径）
```

### 8.3 数据完整性要求
- 原始 CSV 不做任何修改（append-only 理念延伸到归档环节）；确需筛选时另存派生文件并保留原始文件；
- 每个数据集在《数据说明》中登记：文件名、帧数、有效帧数、采集人、设备型号【待填】、运营商【待填】、天气、起止时间。

## 十二、样本量与扇区目标的设定依据

- **每场景 ≥200 点**：1Hz 打点下，绕三圈 + 双横穿 + 定点的标准路线全程约 40～60 分钟，理论帧数 2400～3600 帧；扣除 GPS 精度不达标帧与丢帧后，200 有效帧仅相当于总量的约 6%～8%，是留有充分裕度的下限，用于保证 IDW 栅格化与边界拟合的最低空间密度；
- **方向覆盖度 ≥12/16 扇区**：置信度模型以 16 扇区方向覆盖度为核心因子，12/16（75%）是"中～高置信度"档位的前提；未覆盖扇区将直接拉低置信度并如实反映在输出中，这正是置信度分档设计的验证点；
- **GPS 精度 ≤20m**：城市场景栅格分辨率与缓冲带宽度的经验量级；精度劣于 20m 的帧若保留，会把位置误差直接传导进边界，故判为无效帧（保留原始记录、不参与分析）；
- **定点 ≥5 个（含 1 弱覆盖点）**：定点提供低噪声 RSRP 参考值，用于校核移动采样与静态测量的系统性偏差；弱覆盖定点用于验证"达标/不达标"分界与实际可用性的一致。

> 以上为质量控制口径的推导说明，最终样本量下限以本节目标值为准；实测达成情况【待试验后填写】。

## 十三、数据验收流程

1. **现场核对（采集结束当场）**：App 内查看帧数、方向覆盖度、精度分布，对照第六节 6.3 清单逐项确认，不达标当场补采；
2. **当日归档复核（采集员+记录员双人）**：CSV 可打开、22 列完整、行数与 App 统计一致、记录表与文件一一对应、按第八节命名归档并双备份；
3. **分析前终检（数据分析负责人）**：抽查任一 60s 区间帧间隔是否≈1s、rsrp/targetSeen 字段无异常值（如 -999 哨兵值占比）、轨迹与路线图叠加肉眼复核无飞点；终检通过后该数据集标记"可分析"，方可进入报告第 6 章分析流程。

每个数据集的验收结论登记入《数据说明》："验收状态：通过/有条件通过（注明偏差）/退回补采"。
