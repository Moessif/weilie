# v1.4：入房令牌 + HTTPS 接入说明

## 一、本次新增

| 项 | 内容 |
|---|---|
| 令牌签发 | `POST /api/teams/{roomId}/token`，请求体 `{code,userId,name,role}`，返回 `{token,expiresInSec}`（默认 12 小时） |
| 令牌格式 | `base64url(payloadJson) + "." + base64url(HMAC-SHA256)`；无状态、服务端不落库 |
| 密钥 | 环境变量 `WEILIE_HMAC_SECRET`，否则 `data/hmac.secret`（与照片验签共用） |
| WS 校验 | 连接 `/ws/room/{roomId}?...&token=...`；开启强制后，用令牌里的身份覆盖查询参数，防伪造 userId / 抢队长 |
| 开关 | `WEILIE_REQUIRE_TOKEN=1` 强制；**默认 0（关闭）**，保证旧客户端可继续使用 |
| 客户端 | v0.15.2：进房前自动换令牌并带上 `&token=`；服务端未启用（404/501）时自动回退旧方式 |
| HTTPS | 客户端已支持把 `https://` 服务器地址转成 `wss://`；服务端加 `deploy/Caddyfile` 反代即可 |

## 二、上线顺序（重要）

1. **先升级服务端到 v1.4**，保持 `WEILIE_REQUIRE_TOKEN=0`（只签发、不强制）；
2. 发布客户端 **0.15.2**（会主动换令牌，但服务端不强制，老客户端也不受影响）；
3. 观察 1–2 天，确认绝大多数客户端已是 0.15.2；
4. 在 systemd 单元加 `Environment=WEILIE_REQUIRE_TOKEN=1`，`daemon-reload && restart`；
5. 验证：用旧客户端（0.15.1 及以前）连接应被拒，15.2 正常。

> 若跳过第 2 步直接强制，旧客户端会**无法进房**（不是断线重连问题，是握手被拒）。

## 三、接口示例

```bash
# 1) 换令牌
curl -s -X POST http://47.89.181.85:8080/api/teams/<roomId>/token \
  -H 'Content-Type: application/json' \
  -d '{"code":"834543","userId":"u1","name":"张三","role":"CAPTAIN"}'
# -> {"token":"eyJyb29t...","expiresInSec":43200}

# 2) 带令牌连接（客户端内部完成；手工验证可用 websocat）
websocat "ws://47.89.181.85:8080/ws/room/<roomId>?userId=u1&name=张三&role=CAPTAIN&token=<token>"
```

## 五、HTTPS 步骤（与令牌独立）

1. 域名 A 记录指向 ECS；
2. 安装 Caddy，使用 `deploy/Caddyfile`（已含 WebSocket 反代）；
3. 安全组只放行 443（8080 收回内网）；
4. 客户端「服务器地址」填 `https://你的域名`（会自动走 `wss://`）；
5. 验证：`curl https://域名/api/health`。

## 六、注意事项

- 令牌有效期 12 小时，长时走测不需要重新换取；断线重连沿用同一 token；
- `hmac.secret` 丢失会导致**所有旧令牌失效**（重新登录/换令牌即可），并影响照片验签；
- 令牌只解决“身份不可伪造”，不解决“谁可以加入”——加入仍凭 6 位队伍码，建议配合口令/审批使用；
- 照片上传/下载接口目前**未强制令牌**（客户端尚未携带），下一轮再收紧。

## 七、如何确认客户端已升级（token 审计）

服务端在签发令牌时会写一条审计：

```json
{"ts":1731600000000,"action":"token","roomId":"df9ee158fe5f","userId":"u-1001","detail":{"role":"CAPTAIN"}}
```

- 有这条记录 = 该客户端已经是 0.15.2+；
- 没有这条记录 = 老客户端（仍在用旧握手）。

查询：

```bash
grep '"action":"token"' /opt/weilie/data/audit.jsonl | tail -20
```
