# v0.12.3 — 「用本机当前基站」一键设为目标

> 版本：`versionCode 29` / `versionName 0.12.3`  
> 触发：用户「在目标设置阶段，多加一个按钮，可以将当前手机卡连接的基站快捷设置为跟踪目标」

## 一、交互

新建走测任务页 → 目标参数卡片，输入框下方新增一枚整宽次要按钮：

```
[ 用本机当前基站 ]
已填入：中国移动 · NR N41 · 1386046-4
```

点一下之后：

1. 读取本机 **数据卡当前注册小区**（4G 用 ECI，5G 用 NCI）；
2. 自动填入输入框，例如 `NCI 5677244420` / `ECI 47108`；
3. 自动跑规格校验，通过后加入「已保存的目标」并选中为本次目标；
4. 下方留一行提示「已填入：运营商 · 制式 频段 · gNB-CID」，便于核对是不是要测的那个站。

按钮读取期间禁用并显示「正在读取本机基站…」；失败不写入任何占位值。

## 二、口径（为什么这样拼）

- **5G（NR）→ `NCI <原始 36bit 值>`**，解析器见 NCI 前缀按 5G 处理；
- **4G（LTE）→ `ECI <原始 28bit 值>`**；
- **2G/3G 不支持**（`WCDMA/GSM/CDMA` 返回失败）：`SimCell` 里没有 LAC，拼不出合规的「LAC+CI」，宁可不填也不给错参数；
- **双卡时跟数据卡走**：优先取快照里 `serving.ci`（数据卡注册小区）对应的那一行 SIM；匹配不到才按「NR 优先 → LTE」兜底；
- 读不到小区（飞行模式/无卡/系统不返回）时 toast「读不到当前基站：确认已插卡，并允许「电话」与「定位」权限」，不写伪参数。

## 三、权限

`READ_PHONE_STATE`（订阅与小区信息）+ `ACCESS_FINE_LOCATION`（`getAllCellInfo` 的硬性前置）。

- 两者都缺或只剩一个时，点按钮会先弹系统授权；
- 拒绝后 toast 说明需要哪两个权限，不进入读取；
- 权限通过后直接读取，不需要重启页面。

## 四、实现位置

| 文件 | 作用 |
| --- | --- |
| `ui/task/NewTaskScreen.kt` | 按钮 UI、权限申请、`startFillFromCell()`（填入 + 自动入清单 + 选中）、`readServingCellInput()`（临时 `AndroidCellReader`：start → 最多轮询 2 s → stop，读完即释放，不在任务页常驻监听） |
| `core/telephony/CellTargetShortcut.kt` | 新文件：`rawOf(sim)`（NR→NCI / LTE→ECI / 其它 null）、`hintOf(sim)`、`pick(sims, servingCi)`（数据卡优先，NR→LTE 兜底） |
| `core/telephony/AndroidCellReader.kt` | 复用既有快照（`sims` / `serving`），无改动 |

为什么临时 new 一个 reader：任务还没创建，全局 `SamplingController` 尚未绑定；这里只需要一次读数，读完立刻 `stop()`。

## 五、测试

- 新增 `app/src/test/java/com/gakj/weilie/core/telephony/CellTargetShortcutTest.kt`（7 例）：
  - NR → `NCI 5677244420`；
  - LTE → `ECI 47108`；
  - 2G/3G → null；
  - `cellId <= 0` → null；
  - 提示文案（`中国移动 · NR N41 · 1386046-4` / `中国移动 · LTE B1 · 184-4`）；
  - 双卡时跟着数据卡的 `servingCi` 走，匹配不到才 NR 优先；
  - 空列表 → null。
- 全仓：**23 个测试类 / 175 用例 / 0 失败**。
