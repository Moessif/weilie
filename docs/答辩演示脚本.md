## 四、2 分钟预设问答（10 条）

### Q1：为什么普通手机能测基站覆盖？原理依据是什么？

**答**：智能手机本身就在持续接收蜂窝网络的广播信息。Android 公开 API `TelephonyManager.getAllCellInfo()` 能免 root 返回服务小区与邻区的小区标识、频点与 RSRP/RSRQ/SINR 等物理层测量值——这些是网络广播给所有终端的公开信息，不需要任何特权。我们做的是把这些「每部手机本来就在产生的观测」以毫秒时戳记录下来，再用算法把它们组织成覆盖边界。普通手机能测，本质是因为它本来就是网络设计中的测量参与者。

### Q2：测出来的精度如何辩护？误差多大？

**答**：分三层。第一，**读数层（定标中）**：我们设计了与成熟商用软件 CellularPro 同机同小区的对拍金标准，判据为 RSRP 均值偏差 ≤ 2 dB、小区标识字段完全一致，对拍数据正按《试验数据采集计划》回填（方法见研究报告 5.2，数据表 5-2）；第二，**定位层**：GPS 精度大于 60 米的样本直接剔除，并且把平均定位精度的一半显式加进缓冲带宽度——定位越差边界自动越保守，误差不隐藏；第三，**边界层**：以径向信号剖面法构造金标准边界，实测边界平均偏差与面积收敛率（数据见表 5-3，现场可引用实测值）。我们给指挥员的不只是一个圈，而是「带误差说明的圈」。

### Q3：与运营商的数据是什么关系？有运营商数据不是更快吗？

**答**：运营商的场强图和工程参数是理想的先验资料，但基层民警在办案窗口期往往拿不到完整授权数据，能拿到的就是一条小区标识。本作品不替代运营商数据，而是在「只有一条编号」的现实约束下提供快速的实地核实手段；若能同时获得运营商场强图，本系统导出的实测边界正好用于校核和更新它。两者是补充关系。

### Q4：合规性如何保证？会不会触碰侦查权或通信监管红线？

**答**：四条硬约束。第一，**只观测、不注入**：只读取手机被动接收的广播信息，不解码信令、不锁网锁频、不做测速和测试计划，对网络零干扰；第二，**权限最小化**：不申请 READ_PHONE_STATE，全部能力来自公开 API；第三，**知识产权干净**：全自研代码，不复制任何第三方应用的代码或资源；第四，**使用边界明确**：应用内置法律声明，限定依法执行职务和授权教学场景，不存储任何个人通信内容。取证照片同样做了可信性收敛——影像验真只提供「照片未被修改、确由某设备某时某地登记」的第三方可复核证据，不代断照片内容是否摆拍。我们不是在打监管擦边球，而是把功能负面清单写进了设计文档。

### Q5：手机不是警用专网终端，办案现场没信号/没网怎么办？

**答**：架构上特意做了「离线优先」：采集和拟合全部在手机本地完成，数据 JSONL 落盘，断网只影响「实时共享」这一个环节；恢复网络后自动续传。协同服务器也支持私有化部署——阿里云只是一键部署的演示形态，比赛和实战都可以部署在公安内网或现场便携热点+笔记本上。

### Q6：为什么不用一台贵一点的专用设备/路测仪，而要用多台普通手机？

**答**：两个原因。经济上，路测仪数万到数十万元，县分局配不起——我们的目标用户恰恰是装备空白单位；效能上，单人单机走一圈既慢又容易留盲区，四部手机分片围测五分之一的时间就能铺满 16 个方位。我们的置信度模型里「16 扇区方向覆盖度」占一半权重，多人协同直接推高结论可信度。多台普通手机不是廉价替代品，而是作业模式上的更优解。

### Q7：拟合算法的核心思路是什么？为什么用凸包而不是更复杂的模型？

**答**：核心思路是「多源融合、交叉判读」：凸包给出人到过的紧致范围，缓冲带把定位不确定度显式编码进去，IDW 插值+等值线给出信号物理衰减边界，置信度把样本量和方向完整性量化成分数。选凸包而非克里金/高斯过程等复杂模型，是因为任务要求「可解释、可复算、可离线、秒级响应」：凸包结果一线民警一眼能懂，纯 JVM 实现有单元测试兜底，8 个样本就能出第一版边界。工程上合适的模型优于学术上复杂的模型。

### Q8：数据存在哪里？会不会泄露办案信息？

**答**：三层控制。采集数据只存本机会话文件（append-only，不可篡改）；协同数据只在用户自建的协同服务器内存与本地快照中，不经过任何第三方平台；导出文件由办案人员自行管理。地图 key、AI key 均用户自备自配，我们不内置任何密钥，也不上传任何数据。

### Q9：项目的创新点里，哪一条最难做？你们怎么验证它是对的？

**答**：最难的是覆盖边界拟合的工程化——论文里的算法好写，但要在真机上面对样本稀疏、GPS 漂移、机型字段差异。我们的做法：算法层全部纯 JVM 化，配套单元测试覆盖退化输入；真机层先与商用软件对拍定标采集链路，再设计六个场景（城市/城郊/山区/室内/边界收敛/协同演练）逐一实测，用金标准边界量化误差。结论都有数据表支撑，不是演示效果。

### Q10：后续有什么计划？离实战部署还差什么？

**答**：三条线。一是机型矩阵扩展，系统标定各品牌 CellInfo 字段差异；二是算法增强，引入扇区方位角先验与地形修正，提升山区精度；三是指挥系统对接，把 GeoJSON 输出标准化为服务接口。离实战部署差的其实是「数据」而不是「功能」——六场景实测数据回填后即可形成推广版作业规程，我们还准备了录制回放培训模式用于基层教学。

### Q11（备用题，时间富余时使用）：照片验真到底能证明什么、不能证明什么？

**答**：能证明三件事，都可用第三方手段独立复核：登记记录真实存在（服务端注册表可查）、照片内容自登记起未被修改（SHA-256 哈希一致）、登记行为未被伪造（HMAC-SHA256 签名有效，签名原文含验证码、哈希、双时间戳与坐标）。不能证明的是「照片内容没有摆拍」——那是办案人员的判断职责，系统不越界代断。工程上，验真服务已上线运行，离线拍摄先排队、联网自动补登记，不因网络条件损失证据效力。

## 五、彩排与临场要点

1. **掐表**：第 5 幕（边界收敛）占 70 秒，是得分核心，务必完整呈现；第 3 幕（取证验真）是最有画面感的一段，建议完整保留；若整体超时按脚本内冗余对策砍第 1/4/6 幕细节。
2. **演示失败兜底**：任何现场环节失败（信号/网络/设备），立即切预录录屏继续讲，话术：「为节省时间，我们看提前准备的实测录屏」——不要现场排障超过 15 秒。验真环节现场无外网时，改讲离线排队→联网补登记流程（预录录屏兜底）。
3. **问答纪律**：每题控制在 20 秒内答完核心，先给结论再给依据；数据题一律引用「对拍判据 ≤ 2 dB（数据回填中）」「8 样本启动、120 样本饱和」「16 扇区」「50 项单元测试全绿」四个硬数字。
4. **态度红线**：涉及合规的问题不回避、不夸大，主动亮出负面清单；被问到不知道的数据（如实测边界偏差具体值、CellularPro 对拍实测值），答「该场景数据正在实测回填中，方案在研究报告第五章」，不编数。
