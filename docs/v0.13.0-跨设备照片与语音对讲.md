# v0.13.0 跨设备照片、语音对讲与多人页遮挡修复

日期：2026-11-11
版本：`versionCode 32` / `0.13.0`
APK：`weilie\dist\weilie-v0.13.0-debug.apk`（81,414,662 字节，sha256 `B80DBA199F0B169FE666F7FE04EE768B1CED117B1FAF888FDDC9CA430015ABF5`）

## 一、这一版解决什么

用户三条反馈：

1. 「现在多人模式看不到其他队员的照片，我希望能看见其他人标的图片」
2. 「给这个语音对讲实现了」
3. 「其他手机上的 UI 重叠问题严重」（图层面板压住房间条、成员 chip、右侧按钮与底部栏）

## 二、跨设备查看取证照片

### 之前为什么看不到

- 照片文件只存在拍摄者的手机上（`PhotoStore` 落在应用私有目录）。
- 服务端 `PhotoRegistry` 只登记「哈希 + 时间 + 坐标 + 验证码」，**不存图片字节**。
- 队友点开房间里的照片标点时，`PhotoDetailSheet` 只查本机记录；本机没有 → 显示「未找到该标点的取证记录」。

### 现在怎么走

```
拍摄者：拍照 → 本地落盘 → POST /api/photo/register 拿 code
        → POST /api/photo/upload?code=CODE 上传原图（手动登记）
        → 广播标点（含 photoCode）
队友：  点标点 → 本机无记录且带 photoCode
        → GET /api/photo/verify?code=CODE 取登记信息
        → GET /api/photo/file?code=CODE 取原图 → 直接显示
```

服务端新增 `PhotoFiles.kt`：

- 目录 `data/photos/<code>.jpg`，单文件上限 8 MB，code 必须匹配 `^[A-Z0-9]{6,12}$`；
- 先写 `.tmp` 再原子 `move`，避免并发下载到半个文件；
- `POST /api/photo/upload?code=`（原始字节流）、`GET /api/photo/file?code=`（image/jpeg）、`GET /api/photo/file/count`。

客户端：

- `PhotoVerifier.uploadFile(code, file)` 与 `fetchRemoteImage(code)`；
- `PhotoDetailSheet` 增加远程图片状态：加载中转圈、有图先显示大图再列登记字段、无图时提示「拍摄设备未上传原图」；
- 取证记录详情副标题会说明照片来源（本机 / 拍摄设备已上传 / 尚未上传）。

**注意**：只有本版之后新拍的照片才会自动上传；旧照片本机仍有，队友端只能看到登记信息，看不到图。

## 三、语音对讲（半双工对讲机式）

- 按住底部「对讲」按钮说话，松开即发送；同一时间只有一个人说（半双工），谁在说地图底部会显示「X 正在讲话」。
- 音频：16 kHz / 单声道 / 16 bit PCM，100 ms 一帧（3,200 字节），base64 后约 4.3 KB/帧；端到端延迟约 200–400 ms，房间 2–6 人时带宽约 43 KB/s。
- 协议新增三帧（两端同步）：`audioStart` / `audioChunk` / `audioStop`，服务端只转发给房间内其他成员（不落库、不进聊天历史）。
- 首次按住会申请录音权限；未授权时点按会弹系统权限框。
- 没有引入编解码器（Opus 等），理由是零编码延迟、实现简单；后续若要省流量可在此协议上换编码。

## 四、多人页遮挡修复

原因：图层浮层固定在屏幕左上，宽度 268dp，没有避让顶部「房间 / 连接状态 / 成员」区域；同时右侧按钮列与底部标记/拍照栏一直显示，窄屏（≈360dp 宽）下互相压住。

修复：

- 用 `onGloballyPositioned` 量出顶部 chrome 高度，图层面板 `top = topChromePx + 8dp`，不再压住房间条与成员 chip；
- 面板 `zIndex(6f)`，`heightIn(max = 屏高 - topChromePx - 200dp)` 且内部可滚动；
- 面板打开时自动收起右侧按钮列、左下聊天浮层、底部标记/拍照栏，关闭后恢复。
