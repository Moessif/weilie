本轮是用户真机反馈（m11686）的三条：

1. 「自由绘制任务范围（点地图落点）」手滑的轨迹和形成的面积要**实时**

## 1. 自由绘制实时化

### 根因
绘制中的预览多边形是作为 `WsMsg.Zone` 传给地图渲染层的，而渲染层的内容指纹只收录
`zones.forEach { append(it.ts) }`；预览 zone 的 `ts` 被写死为 `1L`，所以：
- 第 3 个点成面时画了一次多边形；
- 之后每加一个点，指纹不变 → 渲染器直接 `return` → **预览不再刷新**（看起来"不实时"）。

### 修复
- `ui\team\TeamRoomScreen.kt`
  - 预览 zone 的 `ts` 改为 `drawPts.hashCode().toLong()`（内容变 → 指纹变 → 重绘）。
  - `MapCanvas(...)` 新增 `draftPath = if (drawMode) drawPts.toList() else emptyList()`。
  - 绘制条实时显示面积：`ConvexHull.area(drawPts.map { Geo.toLocal(...) })`，
    ≥3 点才显示；`< 1 公顷` 显示 `m²`，否则显示 `公顷`（两位小数），
    新增 `private fun fmtArea(m2: Double): String`。
- `ui\map\BaiduMapCanvas.kt`
  - `BaiduOverlayRenderer.render(...)` 新增 `draftPath`（WGS84）参数，
    指纹追加 `draftPath.size + draftPath.hashCode()` 与
    `zones` 的 `polygon.size/polygon.hashCode()`。
  - 绘制手指轨迹：`PolylineOptions().points(...).color(0xE634D399).width(5f).zIndex(7)`。
- `ui\map\MapFacade.kt` / `ui\map\MapCanvas.kt`（Canvas 兜底地图）同步新增 `draftPath`，
  兜底地图用 `Path` 逐段 `lineTo` 画折线。

结果：手指滑过即出现绿色轨迹线，第 3 个点起同时出现半透明多边形，绘制条面积数字随手指变化。

## 2. 换任务后不再残留上一任务的拍照标点

### 根因
`SingleMapScreen` 进入任务时从 `AppGraph.photoStore.list()` **回填全部本机照片**作为地图标点，
并且注释里明确写了"照片是现场证据，不按任务时间过滤"。于是新任务的图上也会出现旧任务的旗子。

### 修复
- `core\photo\PhotoStore.kt`：`PhotoRecord` 新增 `val taskId: String = ""`
  （单人 = 任务 id，多人 = `"room-<roomId>"`；老记录为空，按时间兜底）。
- `ui\camera\PhotoCameraScreen.kt`：新增参数 `taskId: String = ""`，
  一路传给 `private fun savePhoto(..., taskId)` 并写进 `PhotoRecord`。
- 调用点：`SingleMapScreen` 传 `task.id`；`TeamRoomScreen` 传 `"room-$roomId"`。
- 回填过滤：
  ```kotlin
  .filter { rec -> rec.taskId == task.id || (rec.taskId.isBlank() && rec.ts >= task.createdAtEpochMs) }
  ```
  老照片没有 taskId 时用"拍摄时间 >= 任务开始时间"兜底；恢复任务时
  `createdAtEpochMs` 取 manifest 的 `startedAtEpochMs`，所以继续旧任务仍能看到它自己的标点。
- 顺带：进入任务时先 `markers = markers.filterNot { it.photoId.isBlank() }`（清掉上一个任务的手动旗标，
  v0.8.1 起已有此逻辑，这里保留）。

### 兼容性
`index.jsonl` 是追加写的，老行没有 `taskId` 字段。`PhotoStore` 的 Json 配了
`ignoreUnknownKeys = true`，缺字段取默认值 `""`，因此历史记录仍可读。
新增单测 `core\photo\PhotoTaskIdTest.kt` 覆盖：
- 老格式 JSON（无 taskId）能解析，taskId 为空串；
- 新记录 round-trip 后 taskId 保留、标题口径正确。

## 3. 只保留深色模式

用户明确"取消浅色模式 只留深色模式"。三处收口：

- `ui\theme\Theme.kt`
  - `fun resolveDark(spec, systemDark): Boolean` 恒返回 `true`，注释写明产品决策，
    并保留参数（签名统一，调用点不用改）。
  - `ThemeController.readPrefs()` 不再读 `PREF_THEME_MODE`，固定 `ThemeMode.DARK`；
    老版本存过 `LIGHT`/`SYSTEM` 也一律按深色渲染。
- `ui\settings\SettingsScreen.kt`：删掉"跟随系统 / 浅色 / 深色"三个胶囊
  （以及已无引用的 `ModePill` 与 `ThemeMode` import），改为一行「深色模式（固定）」+ 一句说明。
- `MainActivity.applyWindowChrome(dark)`（v0.10.0 已加）继续按 `resolveDark(...)` 设
  `isAppearanceLightStatusBars/NavigationBars` 与窗口底色；深色模式下即"亮图标 + `Bg0` 底"。

主题色（10 个预设 + 自定义色相/饱和度）仍保留——取消的是明暗模式，不是配色自由度。
