# v0.11.1 · 自由绘制双指手势修复

> 反馈：多人模式自由绘制任务范围时，双指一接触屏幕地图就开始「飘」，而且无法放大缩小；
> 期望双指能平稳拖动地图、并且能捏合缩放。

## 一、根因

1. **位移单位错了**：旧实现把双指质心每一帧的位移直接交给 `MapCamera.panBy()`，
   而它算的是 `156543.03392 * cos(lat) / 2^zoom` —— 这是 **256px 瓦片、不含屏幕密度** 的理论米/像素。
   真机 density≈2.6，等于把手指位移放大了约 2.6 倍；再叠加「相机 → 百度地图」异步推送的延迟，
   误差每一帧都累加，松开手时地图已经飘出去很远。
2. **只实现了拖动，没实现缩放**：绘制态为了不让单指把底图拖走，关闭了地图自身的
   `setScrollGesturesEnabled(false)` / `setZoomGesturesEnabled(false)`，而双指分支只做了平移，
   没有捏合逻辑，所以双指也放不大、缩不小。

## 二、修复

`ui/map/BaiduMapCanvas.kt` 重写绘制态手势（单指画笔保持不变）：

- **起点锚定**：`ACTION_POINTER_DOWN` 时对当前 `mapStatus` 做一次快照（BD09 中心 + zoom），
  并在双指中心用投影实测屏幕 1px 对应的东西/南北米数
  （`screenMetersPerPixel()`：屏幕点偏移 100px 反查经纬度再量距离，天然规避 density 误差）。
- **拖动**：每次 MOVE 都用「相对起点的总位移」一次性换算中心点，不再逐帧累加：
  `lon = startLon - Δx·mppX / (111320·cos(lat))`、`lat = startLat + Δy·mppY / 110540`
  ——手指往哪拖，地图内容就跟到哪（下拖 → 中心北移）。
- **缩放**：`zoom = startZoom + log2(当前双指间距 / 落下时间距)`，clamp 到应用自己的
  `camera.minZoom/maxZoom`（+1 的百度层级偏移），两指张开就放大、捏合就缩小。
- **一次性提交**：每帧用 `setMapStatus(newMapStatus(MapStatus.Builder().target(...).zoom(...)))`
  直接落位，避免动画队列跟不上手指。
- **收尾**：双指抬起后剩下的那根手指不再补点（`strokeBlocked`），全部抬起时把地图状态
  回写 `camera.syncFromMap()`（不递增 revision，防止相机回推造成回环）。
- 单指仍只画线不移动底图；双指不产生任何采样点。

## 四、真机自测清单

1. 多人 → 队长 → 进入任务地图 → 任务 → 自由绘制任务范围；
2. 单指按住拖动画线，轨迹与面积实时更新、底图不跟着动；
3. 双指落下后拖动：地图平稳跟手移动，不再飘；
4. 双指张合：可以放大 / 缩小，且缩放后继续拖动仍然跟手；
5. 双指抬起不应产生额外的点；
6. 撤销一点 / 重画 / 完成仍然正常，完成后任务面板出现多边形任务区。
