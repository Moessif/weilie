# 团队协作与发布流程

面向多人共同维护本仓库的最小约定，不需要额外工具。

## 一、把队友加进来（仓库所有者操作一次）

GitHub 仓库 → `Settings` → `Collaborators` → `Add people` → 输入队友的 GitHub 用户名/邮箱 → 选择权限：

- **Write**：可以直接推分支、提 PR（推荐给一起写代码的人）
- **Maintain**：还能改仓库设置、管理 PR（推荐给长期负责的人）
- **Read**：只能看（给只看代码的人）

队友接受邮件邀请后，即可：

```bash
git clone https://github.com/Moessif/weilie.git
cd weilie
git checkout -b feat/我的改动
# 改代码、本地构建、提交
git push -u origin feat/我的改动
```

然后在 GitHub 上点 **Compare & pull request**，由另一人 review 后合并。

> 如果队友没有 GitHub 账号，也可以让对方用 `git bundle` 或直接发补丁；但 PR 流程最省事。
> 若仓库要保持公开，**不要把服务器口令、HMAC 密钥、云 AK 提交上来**（`.gitignore` 已排除常见路径，仍请自查）。

## 二、分支与提交

| 场景 | 分支名 | 说明 |
| --- | --- | --- |
| 新功能 | `feat/<主题>`，如 `feat/silent-track-v2` | 一个分支一件事 |
| 修 bug | `fix/<主题>`，如 `fix/nsa-anchor-display` | 关联 Issue 时在描述里写 `#12` |
| 文档 | `docs/<主题>` | 不改代码 |
| 发布 | 直接在 `main` 打 tag | 见下 |

提交信息格式：

```
<模块>: <做了什么>

android | server | admin-web | docs | tools
示例：
android: 修复静默跟踪在 NSA 下状态抖动
server: 照片上传增加内容哈希校验
docs: 补充 v0.22.0 变更说明
```

## 三、本地自测（合并前至少跑一遍）

```bash
# 客户端
cd android && ./gradlew :app:testDebugUnitTest :app:assembleDebug

# 服务端
cd server && ./gradlew test fatJar

# 管理站
cd admin-web && pnpm install && pnpm run build
```

改动涉及协议（`Protocol.kt`）时，客户端与服务端要一起改、一起提。

## 四、发布新版本（Releases）

1. 改版本号：
   - 客户端：`android/app/build.gradle.kts` → `versionCode` +1、`versionName`
   - 服务端：`server/src/main/kotlin/.../Application.kt` → `SERVER_VERSION`
   - 管理站：`admin-web` 里展示版本的位置（`AdminLayout.vue` / `LoginPage.vue`）
2. 构建产物：

   ```bash
   cd android && ./gradlew :app:assembleDebug
   cp app/build/outputs/apk/debug/app-debug.apk ../weilie-vX.Y.Z-debug.apk

   cd ../admin-web && pnpm run build
   # 把 dist 内容拷到 ../server/src/main/resources/admin/
   cd ../server && ./gradlew test fatJar
   cp build/libs/weilie-server-all.jar ../weilie-server-vX.Y.Z-all.jar
   ```

3. 在 GitHub 建 tag 与 Release（`Draft a new release`），tag 形如 `v0.22.0`，正文写本版变更（可摘 `docs/vX.Y.Z-*.md`）。
4. 把 `weilie-vX.Y.Z-debug.apk`、`weilie-server-vX.Y.Z-all.jar` 作为 Release 资产上传。
5. 仓库里只提交源码与文档（`*.apk`、`*.jar` 已被 `.gitignore` 排除）。

## 五、部署到服务器（简要）

```bash
# 本地
cd server && ./gradlew test fatJar

# 上传并替换（示例：scp）
scp build/libs/weilie-server-all.jar user@<server>:/opt/weilie/weilie-server-all.jar

# 服务器
ssh user@<server> 'systemctl restart weilie && sleep 5 && curl -s http://127.0.0.1:8080/api/health'
```

首次部署、环境变量、数据备份与回滚见 `docs/admin/运维手册.md` 与 `server/README.md`。

## 六、常见问题

| 现象 | 处理 |
| --- | --- |
| 客户端跑起来地图空白 | 百度 AK 是否绑定了当前包名 + 签名 SHA1；模似器需联网 |
| 服务端 403 `MUST_CHANGE_PASSWORD` | 超管首次登录必须先改密（管理站会自动引导） |
| 管理站打开是空白页 | 忘了把 `admin-web/dist` 拷进 `server/src/main/resources/admin/` 后重新打包 |
| 手机连不上服务器 | 「设置 → 服务器地址」是否指向正确 IP；服务器 8080 是否放行 |
| 队友推送被拒（non-fast-forward） | `git pull --rebase` 后再推；不要强推 `main` |
